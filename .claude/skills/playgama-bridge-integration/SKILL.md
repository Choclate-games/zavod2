# Playgama Bridge v2: интеграция и доказательство

Эта скилла существует потому, что интеграцию Playgama SDK нельзя считать
сделанной по факту написанного кода. Код, который компилируется, проходит
ревью и выглядит правильно, регулярно оказывается **полностью нерабочим**:
подписка на событие с опечаткой молча не срабатывает, `showRewarded()` не
возвращает промис — и `await` на нём выдаёт награду мгновенно, без просмотра
рекламы. Ни компилятор, ни тесты, ни смоук-запуск этого не видят.

Поэтому здесь два обязательных артефакта: **контракт** (что писать) и
**шлюз** (чем доказывать). Без второго первый не работает.

## Шлюз: интеграция не сделана, пока не прошли обе проверки

```bash
# 1. Статический аудит исходников — ловит ловушки, которые компилятор пропускает
node .claude/skills/playgama-bridge-integration/scripts/audit-playgama.mjs workspace/<game>

# 2. Runtime-проверка в настоящем Chromium (Playwright) + yandex-games-debug-checker
node .claude/skills/playgama-bridge-integration/scripts/verify-playgama.mjs workspace/<game>

# 3. То же внутри настоящего черновика Яндекса — с машины, где открыт yandex.ru
#    и выполнен вход в аккаунт разработчика. См. reference/yandex-draft-testing.md
node .claude/skills/playgama-bridge-integration/scripts/verify-playgama.mjs workspace/<game> --draft=<APP_ID>
```

Первые две обязаны выйти с кодом `0`. Третья — обязательна перед отправкой
на модерацию: половина дефектов интеграции существует только внутри iframe
площадки. Отчёты — `<game>/playgama-out/audit.json` и
`<game>/playgama-out/verify.json`, скриншоты панели чекера там же.

Запрещено:
- отчитываться «интеграция готова» без свежих отчётов обеих проверок;
- глушить проверку правкой самой проверки вместо правки игры;
- считать `WARN` чекера «не нашей проблемой», не разобрав каждый.

Если проверка ловит ложное срабатывание — почини правило в скрипте и объясни
в коммите, что именно было ложным. Не добавляй игру в исключения.

## Контракт API: реальный @playgama/bridge 2.x

Полная выверенная поверхность — `reference/bridge-v2-api.md` (снята с
`.d.ts` и бандла пакета, не с документации). Минимум, который надо помнить:

| Что | Как правильно |
|---|---|
| Прогресс загрузки | `bridge.setGameLoadingProgress(0..100)` — **на корне**, не `bridge.game.setLoadingProgress` |
| Готовность | `bridge.platform.sendMessage(PLATFORM_MESSAGE.GAME_READY)` — ровно один раз, после того как меню интерактивно |
| События | `bridge.platform.on(EVENT_NAME.PAUSE_STATE_CHANGED, cb)` — **только константа**, значения `lower_snake` |
| Rewarded | `showRewarded(placement)` возвращает **`void`**. Награда — из `EVENT_NAME.REWARDED_STATE_CHANGED` при `state === 'rewarded'` |
| Interstitial | `showInterstitial(placement)` тоже `void`; окончание — `INTERSTITIAL_STATE.CLOSED`/`FAILED` |
| Хранилище | `bridge.storage.set(key, value)` / `get(key)` — без аргумента типа хранилища |
| Лидерборды | `bridge.leaderboards` — **множественное число** |
| Язык | `bridge.platform.language`, с оговоркой по CrazyGames (см. reference) |
| Гость | `bridge.player.isGuest` — `id`/`name` заполнены и у гостей |

## Ловушки, каждая из которых уже стоила рабочей интеграции

Каждая компилируется, ни одна не падает в рантайме, все — молчаливые.

### 1. Событие подписано строкой с именем константы

```ts
// ❌ подписка на несуществующее событие. Пауза не приходит никогда.
platform.on('PAUSE_STATE_CHANGED', onPause);

// ✅
import { EVENT_NAME } from '@playgama/bridge';
platform.on(EVENT_NAME.PAUSE_STATE_CHANGED, onPause);
```

Имена членов `EVENT_NAME` — `UPPER_SNAKE`, их **значения** — `lower_snake`
(`'pause_state_changed'`). Строка `'PAUSE_STATE_CHANGED'` — валидный
`string`, поэтому компилятор молчит.

### 2. Самописный `interface` вместо типов SDK

```ts
// ❌ этот интерфейс — источник ловушки №1 и №3 одновременно
interface BridgePlatform { on?: (event: string, cb: (v: boolean) => void) => void }
interface BridgeAdvertisement { showRewarded?: (p: string) => Promise<void> }
```

`event: string` принимает любую строку. `Promise<void>` описывает метод,
который на самом деле синхронный и возвращает `undefined`. Оба вранья
попадают в код через объявление собственного типа. **Импортируй типы из
`@playgama/bridge`**, не переписывай их.

### 3. Награда выдаётся по промису

```ts
// ❌ showRewarded возвращает void → await undefined → true мгновенно.
//    Игрок получает награду, не увидев рекламы. Площадка это заметит.
await bridge.advertisement.showRewarded(placement);
return true;

// ✅ награда только из состояния 'rewarded'
advertisement.on(EVENT_NAME.REWARDED_STATE_CHANGED, onState);
advertisement.showRewarded(placement);
// resolve(true) в onState при REWARDED_STATE.REWARDED, resolve(false) при CLOSED/FAILED
```

### 4. Несколько экземпляров сервиса-обёртки

`new BridgeService()` в `main.ts` и ещё один в `Game.ts` — это два разных
`readySent`, два дебаунсера сохранения, две подписки на `pagehide`. Итог:
дублирующийся `game_ready` и потерянный прогресс. **Один модульный
синглтон**, импортируемый везде.

### 5. Watchdog отправляет второй `game_ready`

Сторожевой таймер, создающий новый экземпляр сервиса, обходит флаг
«уже отправлено». Флаг должен жить в синглтоне, а таймер — дёргать его же.

### 6. `game_ready` сразу после `initialize()`

Сплэш площадки уходит с незагруженной игры. Порядок жёсткий:
`initialize()` → ассеты → меню отрисовано → прогресс дошёл до 100 →
пауза на затухание оверлея → `game_ready`.

### 7. Прогресс не сообщается вообще

Если игра молчит, bridge сам вызывает `setProgress(100, true)` через
**700 мс после того, как `initialize()` завершился** — то есть до того, как
игра загрузилась. На закэшированной перезагрузке это видно как «оверлей
исчез → пустой экран → меню».

### 8. `game_ready` в том же тике, что и прогресс 100

Оверлей bridge снимается по расписанию `400 / 900 / 1400 мс` после
`setGameLoadingProgress(100)`. Отправляй `game_ready` через ~600–800 мс
после сотни, иначе сплэш площадки уходит поверх непогасшего оверлея.

### 9. Язык захардкожен

`<html lang="ru">` и русские строки в коде — отказ модерации Яндекса по
п. 2.14. Язык берётся из `bridge.platform.language`, до того как игра стала
интерактивной, с фолбэком `be/kk/uk/uz → ru`.

### 10. Ввод открыт до `game_ready`

Модератор прокликивает загрузку и попадает в неготовую игру — отказ по
п. 1.19. Кнопки меню недоступны (`disabled`/`pointer-events:none`), пока
не отправлен `game_ready`.

### 11. Гость определяется по `player.id`

`id` и `name` заполнены и для гостей (`"Guest V8ZL…"`). Единственная
надёжная проверка — `player.isGuest`.

### 12. UI строится в предположении, что фича есть

Кнопка «Смотреть рекламу» на площадке без rewarded — сломанная кнопка.
Каждый элемент гейтится флагом: `isRewardedSupported`,
`isInterstitialSupported`, `isBannerSupported`, `isAuthorizationSupported`,
`payments.isSupported`, `leaderboards.type !== 'not_available'`.

### 13. Защита страницы отдана bridge

Bridge ставит `user-select: none`, `overscroll-behavior: contain` и
блокирует `contextmenu` — но только после инициализации и внутри своего
бандла, куда статический анализ чекера не видит. Игра обязана объявить это
**в собственном CSS** (`html, body { overscroll-behavior: none; user-select:
none; -webkit-touch-callout: none; overflow: hidden }`) и повесить свои
`contextmenu`/`selectstart` guard-ы.

### 14. Нет `playgama-bridge-config.json`

Мост при `initialize()` первым делом читает `./playgama-bridge-config.json`.
Файла нет — в консоли `CONFIG_LOAD_FAILED`, и это **не только** шум: в
конфиге живут маппинг лидербордов, список товаров, настройки баннеров и
оверлея загрузки. Без него доски и покупки молчат.

Файл кладётся в `public/` (Vite копирует его в корень `dist/`), а не в `src/`.
Минимум — в `assets/playgama-bridge-config.json`.

### 15. Спроектированные плейсменты не подключены

`MONETIZATION.md` описывает три rewarded-плейсмента и покупки, а в коде
`showRewarded` не вызывается ни разу. Аудитор сверяет плейсменты из
`MONETIZATION.md` / `GAME_DATA.yaml` с вызовами в исходниках.

## Обязательная поверхность интеграции

Игра завода считается интегрированной, когда есть всё перечисленное.
Отсутствующее — это дефект, а не «не входило в задачу».

- [ ] Единственный синглтон-обёртка; игровой код не трогает `window.bridge`
- [ ] `initialize()` обёрнут в `Promise.race` с таймаутом 10 с
- [ ] `in_game_loading_started` сразу после `initialize()`, `in_game_loading_stopped` вместе с `game_ready`
- [ ] Прогресс идёт монотонно 0 → 100 своими вызовами
- [ ] `game_ready` ровно один раз, после меню, с паузой после сотни
- [ ] Ввод заблокирован до `game_ready`
- [ ] Язык из `platform.language` + фолбэк, применён до интерактивности
- [ ] `PAUSE_STATE_CHANGED` и `AUDIO_STATE_CHANGED` через `EVENT_NAME`, колбэк вызван один раз текущим значением при подписке
- [ ] `gameplay_started` / `gameplay_stopped` вокруг активного геймплея
- [ ] Rewarded через событие, все плейсменты из `MONETIZATION.md` подключены
- [ ] Interstitial с соблюдением минимальной паузы, звук и геймплей встают на время рекламы
- [ ] Сохранение: один ключ, один JSON, дебаунс + флаш на `pagehide`, `localStorage` только зеркало
- [ ] UI построен на флагах поддержки
- [ ] Собственный CSS/JS-guard для правил 1.6.2.7 и 1.10.2
- [ ] Оба отчёта проверок зелёные

## Порядок работы

1. Прочитай `reference/bridge-v2-api.md` — не пиши по памяти.
2. Скопируй `assets/BridgeService.ts` в `src/platform/` и адаптируй под
   форму сохранения игры. Это эталон, а не пример: расхождения с ним
   должны быть осознанными.
3. Подключи плейсменты из `MONETIZATION.md`.
4. Прогони `audit-playgama.mjs`, почини всё, что он нашёл.
5. Прогони `verify-playgama.mjs`, почини всё, что он нашёл.
6. Разбери каждый `WARN` чекера: либо исправлено, либо в коммите написано,
   почему для этой игры это не применимо.

## Чекер Яндекса

`verify-playgama.mjs` подтягивает `debugcheck.js` из
`Nioris/yandex-games-debug-checker` (закреплённая версия, кэш в
`.claude/skills/playgama-bridge-integration/.cache/`), инжектит его в
собранную игру и снимает панель результатов.

Важная особенность: чекер написан под **прямой** Yandex SDK
(`YaGames.init()`, `LoadingAPI.ready()`). Игра на Playgama Bridge вызывает
их внутри бандла, поэтому часть статических проверок честно не находит
сигнатуры в исходниках. Скрипт помечает такие пункты как `bridge-mediated`
и проверяет их своим runtime-наблюдением за мостом, а не подгонкой
исходников под grep чекера. Все остальные пункты — про саму игру и должны
быть исправлены в игре.

Соответствие пунктов требований Яндекса и того, чем оно закрывается —
`reference/yandex-moderation-map.md`.

### Ложные срабатывания чекера

Часть правил чекера — регулярки по **минифицированному бандлу**, и они
ошибаются. Живые примеры из этой игры: `qs=700,$s=45` (имена переменных
после терсера) прочитано как цену «700 $»; русское слово «гребёнка» поймано
правилом про брань из-за стема «ебё»; `new Audio(` найдено внутри бандла
самого моста, который так проигрывает свой звук загрузки.

Такие пункты **не удаляются и не замалчиваются**. Они переезжают в
`playgama-verify.json` рядом с игрой:

```json
{
  "checkerAcknowledged": [
    { "match": "No profanity", "reason": "Совпадение на слове «гребёнка» — стем «ебё» внутри чистого слова; проверено grep-ом по src/." }
  ]
}
```

Проверка печатает их отдельным блоком вместе с причиной и кладёт в отчёт.
Причина короче 20 символов игнорируется: файл нужен для разбора, а не для
того, чтобы гасить неудобное. Прежде чем добавлять запись — найди
совпадение своими глазами и убедись, что оно ложное.
