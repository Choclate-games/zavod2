# Проверка сборки внутри настоящего черновика Яндекс Игр

Официальная процедура: `yandex.ru/dev/games/doc/ru/console/test-game`.

Локальный dev-сервер отдаёт игру, а открывается она **внутри фрейма Яндекса**
— то есть с настоящим `sdk.js`, настоящей авторизацией, настоящей рекламой и
настоящим сплэшем. Ни один локальный прогон этого не заменяет: половина
дефектов интеграции существует только внутри iframe площадки.

## Команда

```bash
npm run build
npx @yandex-games/sdk-dev-proxy -p ./dist --app-id=<APP_ID> -c --port 8099
```

`-c` открывает браузер на собранном адресе:

```
https://yandex.ru/games/app/<APP_ID>/?draft=true&game_url=https://localhost:8099
```

Прокси поднимает **https** с самоподписанным сертификатом — Яндекс не
подгрузит игру по http во фрейм. Браузер один раз попросит принять
сертификат `https://localhost:8099`; без этого фрейм останется пустым.

## Через проверку из этой скиллы

```bash
node .claude/skills/playgama-bridge-integration/scripts/verify-playgama.mjs \
    workspace/<game> --draft=<APP_ID>
```

Режим черновика делает то же самое, но прогоняет внутри фрейма весь набор
проверок: порядок загрузки, подписки, контракт награды, сохранение, чекер
модерации. Браузер запускается видимым — иначе не пройти авторизацию.

## Что нужно, чтобы это заработало

1. **Доступ к `yandex.ru`.** В облачной песочнице завода домен закрыт
   политикой egress: `CONNECT tunnel failed, response 403`. Режим черновика
   запускается только с машины, у которой есть обычный доступ в интернет.
2. **Вход в аккаунт разработчика**, которому принадлежит черновик. Без
   сессии консоль отдаст 404 на `?draft=true`.
3. **Node не читает `HTTP_PROXY`.** Если машина ходит в сеть через локальный
   прокси, `sdk-dev-proxy` не сможет забрать `sdk.js`, вернёт 500, и SDK
   молча не инициализируется. Симптом — вечная загрузка без ошибок в консоли.

Постоянный профиль браузера удобно держать отдельно, чтобы авторизация
переживала перезапуски:

```bash
node scripts/verify-playgama.mjs workspace/<game> --draft=<APP_ID> --headed
```

## Два профиля, а не один

Гость и авторизованный игрок идут разными путями через авторизацию,
хранилище и покупки. Часть блокеров воспроизводится **только у гостя** —
например, бутстрап, припаркованный на `await authorize()`, для которого
гостю никогда не показали диалог. Прогонять оба.

## Режимы отладки консоли

К адресу черновика добавляется `&debug-mode=<N>`. Практически полезен режим
панели `TestDebugPanel`: она печатает `The game called "ready" after X ms`.
На закэшированной перезагрузке это число должно быть **≥ ~1000 мс** — меньше
означает, что игра не дождалась ни прогресса, ни затухания оверлея.

## Что смотреть глазами, чего не увидит ни один скрипт

- Сплэш Яндекса уходит на уже нарисованное меню, а не на пустой экран.
- Оверлей моста успел погаснуть до того, как ушёл сплэш площадки.
- Межстраничный ролик ставит игру на паузу и глушит звук, а после закрытия
  игра не «догоняет» накопленное время рывком.
- Rewarded, закрытый на середине, не даёт награды.
- Баннер не перекрывает игровое поле (требование 4.4).
- Перезагрузка сохраняет прогресс — и у гостя, и у авторизованного.
