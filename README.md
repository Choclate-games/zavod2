# AI Game Prompt Factory 🎮⚡

**AI Game Prompt Factory** — локальное приложение на Python, которое по текстовому описанию идеи игры автоматически создает полный пакет проектной документации, визуальный concept preview и финальный промпт для AI coding agent.

> **Главный принцип:** Это генератор исчерпывающих спецификаций и инструкций для создания игр, превращающий сырую идею в согласованное, качественное и исполнимое ТЗ (`AI_DEVELOPER_PROMPT.md`), готовое к передаче coding agent'у без необходимости повторного проектирования игры с нуля.

---

## 🚀 Возможности

- **Полный ролевой Pipeline агентов**:
  - `ProjectDirector` — разводит идею на 3 разных направления (разный глагол игрока, форма сессии и камера), выбирает одно с обоснованием и фиксирует, **чем проект НЕ является** (`PROJECT_DIRECTION.md`).
  - `IdeaAnalyzer` — деконструкция идеи внутри выбранного направления: жанр, fantasy, hook, ЦА.
  - `GameDesigner` — core loop, win/lose, сессионная модель, прогрессия.
  - `ReferenceAnalyst` — подбор и деконструкция паттернов из базы референсов.
  - `MechanicsArchitect` — проектирование механик с физикой, инпутом, фидбеком и edge-кейсами.
  - `KnowledgeCurator` — подбирает документы `knowledge/` под конкретный проект (а не выдаёт всю базу каждому) и объясняет, что осознанно не взял. Набор обязан быть широким: девять осей (производительность, физика, геометрия мира, тела в кадре, подача, звук, монетизация, стек, петля) закрываются хотя бы одним документом каждая, а незакрытые добираются автоматически — узкий набор вокруг главной механики оставлял шутер без рэгдолла и без бюджета кадра.
  - `RendererSelector` — конфигурация стека **Three.js** + Rapier3D под жанр.
  - `TechnicalArchitect` — модульная TypeScript/Vite архитектура, системы, зависимости.
  - `PlaygamaSpecialist` — полноценная интеграция Playgama Bridge (Ads, Storage, Cloud, Leaderboards, Lifecycle).
  - `MonetizationDesigner` — баланс Rewarded видео, Interstitials, IAP и экономика.
  - `ArtDirector` — стиль, палитра, освещение, шейдеры, VFX, камера и HUD.
  - `UXDesigner` — мокапы интерфейса, mobile touch controls (виртуальные стики, свайпы).
  - `PreviewDesigner` & `PreviewGenerator` — генерация концепт-скриншота игрового процесса (`concept_preview.png`) и промпта (`PREVIEW_PROMPT.md`).
  - `SkillGenerator` — game-specific и специализированные скиллы в формате Markdown.
  - `SelfCritiqueAgent` & `ConsistencyValidator` — валидация согласованности и полноты всех документов.
  - `PromptCompiler` — компиляция мастер-промпта `AI_DEVELOPER_PROMPT.md`: уровни обязательности (MUST / SHOULD / MAY), порядок работы, контракт модулей, роадмап, связанный с номерами проверок. Правила площадки, которые пакет везёт ещё и скиллом, в промпт не вклеиваются третьим экземпляром — но только если этот скилл в пакете действительно есть.

- **Провайдеры ИИ**:
  - `agy` — **Google Antigravity CLI** (отправляет идею в `agy`, который структурирует задачу, после чего Python компилирует полный пакет ТЗ).
  - `opencode` — **OpenCode Go / Zen Подписка** (доступ к специализированным моделям для кодинга через API `https://opencode.ai/zen/v1`).
  - `local` — **отключён**. Экспертный эвристический движок работал без сети и
    без ключей, но при недоступном провайдере прогон не падал, а молча собирал
    пакет заготовками: на выходе получался полный и валидный проект, не имеющий
    отношения к введённой идее. Фабрика работает только онлайн; код заготовок
    оставлен в `providers/local.py` и закомментирован по входам.

- **Прогон живёт в проекте с первой секунды.** Каталог проекта и чат заводятся до
  первого вызова модели, а не после последнего: `workspace/<слаг>/.factory/run/`
  хранит статусы шагов и снимок концепции, а ход прогона — повторы, паузы,
  ответы агентов — пишется сообщениями в обычный чат проекта, тот самый, что
  виден на вкладке «💬 Чаты разработки». Когда спецификация собрана, разговор в
  нём продолжается уже с кодовым агентом.
  Осечка провайдера лечится повтором (`AGENT_RETRY_ATTEMPTS`,
  `AGENT_RETRY_BACKOFF_SECONDS`); если повторы не помогли, прогон не падает, а
  приостанавливается — `runs` покажет, где он встал, `continue <прогон>` продолжит
  со следующего шага, не переспрашивая модель о том, что она уже ответила. В вебе
  отдельной вкладки для этого нет: прогон — обычный чат проекта, помеченный 🏭,
  и кнопка «▶ Продолжить прогон» живёт прямо в нём. Пока у игры нет названия,
  чат называется «Прогон N»; как только концепция получает заголовок, чат и сам
  проект переименовываются в название игры.
  - `openai` — интеграция с GPT-4o и DALL-E 3.
  - `anthropic` — интеграция с Claude 3.5 Sonnet.
  - `google` — интеграция с Google Gemini.

- **Приёмка пакета** — `ACCEPTANCE.md` рядом с игрой: пронумерованные проверки
  вместо обещаний, от `A1` (сборка) до `E5` (адаптивное качество). Статическая
  часть исполняется: `scripts/check-spec.mjs` уезжает в каждый пакет без
  зависимостей и ловит литералы цвета мимо темы, эмодзи вместо иконок,
  непрозрачную заливку поверх игровой сцены и отсутствующий `game_ready`.
  Платформенные критерии дописываются в приёмку всегда, а не только когда
  модель оставила поле пустым.
- **Числа игры** — `balance.yaml`: параметры механик становятся данными, а
  правка баланса перестаёт быть правкой кода.
- **Готовый код фабрики** (`knowledge/mechanics/CATALOG.yaml`, 67 модулей из
  стенда) — не список идей, а рабочие модули: `stealthSensing.ts` с конусом
  зрения и шкалой подозрения, `shooterRagdoll.ts` с рэгдоллом без физдвижка,
  `AudioManager.ts` со звуком без единого mp3. Каталог включается на этапе
  РЕАЛИЗАЦИИ, а не идеи: сначала модель придумывает механики сама, потом
  фабрика отвечает, что из придуманного уже написано. Восемнадцать модулей не
  имеют ни одного импорта и копируются как есть.
- **База знаний по требованию** — пакет игры больше не носит двести килобайт
  дословных копий (из которых 91 КБ был буквальными дублями: один документ в
  двух скиллах сразу). Он носит `knowledge.manifest.json` и
  `scripts/fetch-knowledge.mjs`: одна команда кладёт нужное в `docs/ref/`, и
  дальше прогон идёт офлайн. Адрес — Contents API GitHub, приватный
  репозиторий отличается от публичного только заголовком с токеном; сам токен
  живёт в `.env` фабрики и в папку игры не попадает никогда.
- **Дизайн пишет кодовый агент.** Готового арт-дирекшена в пакете нет: дизайн,
  продиктованный списком полей, получается одинаковым от игры к игре. Фабрика
  даёт рамки, запреты и чек-лист, агент первым делом пишет `DESIGN.md`, а
  приёмка проверяет результат (проверка **F1**).
- **Проверка на противоречия** — валидатор ищет места, где промпт спорит сам с
  собой: запрет из рамки проекта, вернувшийся в тело промпта требованием.
  Так нашёлся виртуальный джойстик, которого игра прямым текстом не хотела.

- **Веб-интерфейс** (главное приложение, `start.bat` или `python run_web.py`) —
  локальный сервер FastAPI + одностраничный клиент в браузере. Те же вкладки,
  что и в десктопной версии, но без рывков Tk: длинные операции идут в фоне,
  а браузер получает их ход по Server-Sent Events.

- **Десктопный GUI на CustomTkinter** — ⚠️ **устарел и не развивается**
  (`python gui.py`). Оставлен в репозитории для совместимости; новые
  возможности приезжают только в веб, расхождения с ним багами не считаются:
  - **🚀 Студия генерации** — создание игры под ключ из одной идеи.
  - **📁 Проекты и ТЗ** — инспектор проектов, Markdown-вьюер, журнал разработки
    (`DEVLOG.md`) и changelog игры.
  - **⚡ AGY CLI Терминал** — чат с кодовым агентом по выбранному проекту;
    режим «Продолжать диалог» помнит предыдущие задачи и позволяет вести
    разработку итерациями.
  - **🌐 Играть (браузер)** — запуск `npm run dev` и открытие игры во внутреннем
    окне браузера прямо из фабрики.
  - **📊 Квоты агентов** — отдельный экран с 5-часовым и недельным лимитами,
    временем сброса и историей запросов, обновляется автоматически. Там же —
    расход токенов: сколько сожгла фабрика целиком и каждый проект по
    отдельности.
  - **⚙️ Настройки API** — ключи, провайдеры и каталог песочницы.

- **Песочница `workspace/`**: все проекты создаются в `workspace/<slug>/`, и
  кодовому агенту разрешена работа только внутри каталога его проекта. Агент
  обязан вести `DEVLOG.md` и `CHANGELOG.md` — это часть Definition of Done.

## 🎲 Разнообразие идей и визуальных стилей

- **Каталог идей расширен до 35 концептов** из разных миров: пасека, пекарня, узкоколейка,
  батискаф, раскоп, оркестр, зимовка, реставрация, бонсай, детектив, каперы, муравейник и другие.
  Брейнсторм отдаёт не «первые N», а по одной идее из каждого семейства сеттинга, поэтому
  десять идей приходят из десяти разных миров. Показанные в прошлый раз идеи уходят в конец
  очереди — повторная кнопка «Придумать идею» даёт новый набор.
- **Подсказка темы работает по корню слова**: «гонки» находят «гонка», «кулинария» — «кулинарный»,
  и подходящие идеи всегда идут первыми.
- **Киберпанк перестал быть визуальным умолчанием.** Стиль теперь подбирается по сеттингу игры:
  выжженная пустошь, античность, биолюминесцентный микромир, уютная кухня, толща воды,
  зимний минимализм, ретро-космос, бумага и тушь, театральная сцена, канцелярский коллаж
  детектива и другие — у каждого своя палитра, освещение, VFX и тема интерфейса.
  Неон никуда не делся: он включается, если игрок прямо попросил киберпанк.
- **Жанр и петля тоже следуют сеттингу**: игра про пекарню получает петлю «заказ → сборка →
  подача → апгрейд кухни», а не «волны врагов → босс» только потому, что не совпала с шаблоном.
- **Промпт брейнштормера** требует разброса жанров и сеттингов и запрещает делать киберпанк
  умолчанием — правило уходит и в облачные модели, не только в офлайн-каталог.

## 🌐 Запуск веб-фабрики (основной способ)

```bash
# Windows: двойной клик по файлу или из терминала
start.bat

# Любая система
python run_web.py

# Полезные флаги
python run_web.py --port 7900 --no-browser
```

`start.bat` при первом запуске доустановит зависимости, поднимет сервер и сам
откроет интерфейс в браузере (`http://127.0.0.1:7860` — порт берётся из
`GUI_PORT` в `.env`, занятый порт заменяется следующим свободным).
Сервер слушает только локальный адрес; всё — файлы, CLI-агенты, dev-серверы игр —
работает на вашей машине.

Вкладки веб-интерфейса:

| Вкладка | Что делает |
| :--- | :--- |
| 🚀 Студия генерации | идея → 25+ документов → скиллы → кодогенерация агентом, брейнсторм идей, пакетная генерация, журнал в реальном времени, витрина готовых игр |
| 📁 Проекты и ТЗ | список проектов с превью, просмотр документов (Markdown/исходник), DEVLOG, CHANGELOG, генерация превью, ребилд разделов, экспорт ZIP, валидация |
| 💬 Чаты разработки | параллельные чаты с CLI-агентами по проекту, выбор агента и модели, YOLO, продолжение беседы, стоп, откат последнего запроса, Markdown-вид ответов, внешний терминал |
| 🌐 Играть | `npm run dev` для выбранной игры, вывод сервера, открытие во вкладке или в отдельном окне предпросмотра |
| 📊 Квоты агентов | живые квоты Antigravity, реальные лимиты Claude Code / Codex, ссылка в кабинет OpenCode (остаток есть только там), расход токенов по проектам и по фабрике целиком |
| ⚙️ Настройки | пути к CLI, модели, reasoning effort, каталог песочницы, уведомления — с записью в `.env` |

Отдельное окно предпросмотра использует `pywebview`, если он установлен; иначе
игра открывается в окне Edge/Chrome (`--app`), а в крайнем случае — во вкладке
системного браузера.

### ↩ Откат последнего запроса

Перед каждой задачей в чате фабрика делает снимок проекта в теневом
git-репозитории `workspace/<slug>/.factory/snapshot.git` (собственный `.git`
проекта не трогается, `node_modules/` и `dist/` в снимок не попадают).

Кнопка **«↩ Откатить запрос»** над лентой показывает список изменённых файлов и
возвращает каталог проекта к состоянию до запроса, а пару «запрос — ответ»
убирает из переписки. Откаты идут по цепочке: нажав дважды, вернётесь на два
запроса назад. Беседу CLI-агента отмотать нельзя, поэтому после отката
`conversation_id` сбрасывается и следующая задача начинает новый диалог.

Требуется `git` в `PATH`; без него чат работает как раньше, но кнопка отката
остаётся неактивной.

## 💻 Использование через CLI

### 1. Создание полной спецификации игры

```bash
# Запуск с Antigravity CLI (AGY)
python -m app.cli create "3D гладиаторский roguelike с ragdoll физикой на Яндекс Игры" --provider agy

# Запуск с OpenCode Go (Zen API)
python -m app.cli create "Космический автобатлер и кликер" --provider opencode

# Офлайн-режим убран: фабрика работает только с живой моделью.
# python -m app.cli create "2D карточный рогалик" --provider local

# Интерактивный режим (мастер вопросов)
python -m app.cli create --interactive

# Прогоны: что собрано, что можно продолжить
python -m app.cli runs

# Продолжить прогон, прерванный обрывом связи, — с того же шага
python -m app.cli continue 20260822-210355-nochnaya-smena
```

### 2. Тестирование подключения провайдеров

```bash
# Проверка AGY CLI
python -m app.cli test-provider agy

# Проверка OpenCode Go
python -m app.cli test-provider opencode
```

### 3. Инкрементальная регенерация

```bash
# Перегенерировать документацию
python -m app.cli rebuild-docs 3d_gladiator_roguelike

# Перегенерировать финальный промпт
python -m app.cli rebuild-prompt 3d_gladiator_roguelike

# Перегенерировать концепт-превью
python -m app.cli preview 3d_gladiator_roguelike

# Перегенерировать отдельную секцию
python -m app.cli rebuild 3d_gladiator_roguelike --section monetization
```

### 5. Список проектов и валидация

```bash
# Список проектов
python -m app.cli list

# Валидация пакета
python -m app.cli validate 3d_gladiator_roguelike
```
