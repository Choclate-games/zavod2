# `assets/` — общая библиотека моделей завода

Готовые ассеты, которые агент может взять в игру вместо того, чтобы собирать
модель из боксов. Лежат вне `workspace/` и `output/` намеренно: это библиотека
на все проекты, а не часть одного.

| Папка | Что внутри | Кости | Анимации |
|---|---|---|---|
| `x_bot/X Bot.fbx` | Mixamo X Bot — безликий манекен, «светлый» | 129 (`mixamorig*`, с пальцами) | **нет** |
| `y_bot/Y Bot.fbx` | Mixamo Y Bot — тот же манекен, второй силуэт | 117 (`mixamorig*`) | **нет** |
| `fight_anim/*.fbx` | 40 боевых движений: удары руками и ногами, блоки, уклоны, реакции на удар, падения, подъём | 76, **другой скелет** (`Spine1/Chest/Neck1`) | да, по одной на файл |
| `proc_anim/*.json` | 22 процедурные анимации бойца, снятые с игры: стойка, шаги, присед, уклон, рывок, удары руками и ногами, прыжок, реакции, подъём | любой риг с драйверами по суставам | да, готовые дорожки поворотов |

## Как ими пользоваться

1. **Скопируйте нужный файл в `public/` своей игры** — Vite отдаёт статику
   только из корня проекта, читать `../../assets` из браузера нельзя:

   ```
   cp "assets/x_bot/X Bot.fbx" workspace/<игра>/public/models/x_bot.fbx
   ```

   Дублирование здесь дешевле связности: билд игры остаётся самодостаточным,
   и правка библиотеки не ломает уже собранные проекты.

2. **Грузите через `FBXLoader`** и обязательно нормализуйте: модели Mixamo
   идут в сантиметрах (рост ≈ 180 единиц) и в T-позе.

3. Как надеть на такую модель боевую анимацию, написанную кодом, и как
   отдать её в рэгдолл — `knowledge/threejs/skinned_character_models.md`.
   Рабочий пример: `workspace/knowledge-showcase/src/world/mixamoRig.ts`.

## Клипы из `fight_anim/`

Записаны **не на скелете Mixamo**: кости зовутся иначе, их 76, и rest-поза —
боевая стойка, а не T-поза. Переименованием костей это не совмещается, нужен
ретаргет; рабочий рецепт и грабли — `knowledge/threejs/skinned_character_models.md`
§6, рабочий код — `workspace/knowledge-showcase/scripts/bake-fight-anim.ts`
(`npm run bake:fight-anim`).

Что в наборе есть: `jab_*`, `cross_*`, `hook_*`, `uppercut_*`, `body_punch_right`,
`elbow_strike_right`, `knee_strike`, `front_kick`, `side_kick_right`,
`roundhouse_kick_*`, `spinning_kick`, `back_kick`, `jump_kick`, `sweep_kick`,
`stomp`, `block_high/mid/low`, `parry_right`, `dodge_back/left/right`,
`roll_dodge_forward`, `hit_react_face/chest/body`, `stagger_backward`,
`knockdown_fall`, `knocked_to_knees`, `get_up`, `choke_grab`, `grab_and_throw`,
три связки `combo_*`.

Чего в наборе **нет**: стойки на месте и шагов. То есть ровно того, что
персонаж делает большую часть времени, — это по-прежнему на игре.

Ещё две вещи, которые видно только замером:
* в каждом файле 3–6 секунд, из них движения 0.5–1.5 с, остальное актёр стоит;
* имя файла не говорит, какой рукой удар: `jab_left` — это удар рукой со
  стороны +X. Сверяйтесь замером, а не именем.

## Процедурные анимации `proc_anim/`

Не мокап и не FBX, а JSON с поворотами суставов по кадрам — выгрузка той
анимации, что считает код игры. Нужны там, где мокапа нет или он мешает:
стойка и шаги, привязка к точке на полу, любая длительность. Подробности и
формат — `proc_anim/README.md`.

Пересобирается `npm run make:proc-anim` в стенде — **обязательно после любой
правки поз**, иначе библиотека тихо разойдётся с игрой. `npm run
check:fight-anim` сверяет длительности и знак сгиба коленей прямо в файлах;
на длительностях одних не выехать — число кадров могло не поменяться.

## Чего в этих файлах нет

**Клипов анимации в самих моделях.** У `x_bot`/`y_bot` внутри одна
техническая дорожка `mixamo.com` длиной 0.03 с (один кадр T-позы) — это не
ходьба и не удар. Движение персонажу дают либо код (`mixamoRig.ts`), либо
клипы из `fight_anim/` после ретаргета.

**Текстур.** Оба бота — сплошные цвета в двух материалах: тело и «суставы».
Материалы FBX приходят как `MeshPhongMaterial`; заменяйте на
`MeshStandardMaterial`, иначе персонаж выпадает из освещения сцены.
