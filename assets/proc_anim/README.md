# `proc_anim/` — нормализованные процедурные анимации бойца

Двадцать две анимации гуманоида, **сгенерированные кодом**, а не записанные
с актёра: стойка, шаги, присед, уклон, рывок, восемь ударов руками и ногами
(включая фронт-кик, хайкик и подсечку), прыжок целиком, удары с воздуха,
реакции на попадание, блокстан, слом гарда и подъём с настила.

Формат — тот же, что у запечённого мокапа (`fight_anim` после
`bake-fight-anim.ts`), поэтому оба набора проигрываются одной функцией:

```json
{
  "id": "walk_forward",
  "label": "шаг вперёд",
  "source": "procedural",
  "fps": 60,
  "frames": 90,
  "rootY": [0, -0.01, ...],
  "joints": { "body": [x,y,z,w, ...], "waist": [...], "thighL": [...] }
}
```

* `joints` — локальные кватернионы **драйверов рига**, по четыре числа на
  кадр. Имена совпадают с полями `BoxerRig`: `body, hips, waist, chest, head,
  shoulderL, elbowL, shoulderR, elbowR, thighL, shinL, thighR, shinR`.
* `rootY` — высота таза относительно стойки, метры. Отрицательное — присел
  или лежит.
* `fps: 60` — клипы записаны в игровом тике, пересчёт не нужен.

## Как подключить

Риг должен быть устроен так же: одна группа-драйвер на сустав, оси совпадают
с осями персонажа, конечности в покое смотрят вниз, позвоночник вверх.
Персонаж смотрит в **+Z** — от этого зависит знак: в клипах колено согнуто
вперёд, и на риге, повёрнутом лицом в −Z, ноги вывернутся назад. Как
такой риг сделать из готовой модели (в том числе из `x_bot`/`y_bot`) —
`knowledge/threejs/skinned_character_models.md` §4; проигрывание кадра —
`workspace/knowledge-showcase/src/world/fightClips.ts`.

## Откуда они берутся

`npm run make:proc-anim` в `workspace/knowledge-showcase`: скрипт крутит саму
игру без рендерера, нажимает те же клавиши, что нажал бы игрок, и пишет
повороты драйверов по кадрам. То есть это **не «похожие» анимации, а ровно
те, что в игре**. Мокап на время записи выключается — библиотека обязана
работать там, где чужих клипов нет.

Пересобирать после любой правки поз в `FightingDemo.poseRig()`.

## Чем они хороши и чем плохи

Хороши: ноль зависимостей, ноль байт мокапа, любая длительность
пересчитывается на лету, и главное — они **не спорят с игрой за корень**.
Мокап записан со своим движением таза, и если отдать ему ноги, персонаж
отрывается от земли (см. §6 того же документа).

Плохи: это не мокап. Веса тела и инерции в них ровно столько, сколько заложил
код. Для крупного плана лучше смешивать: ноги и таз отсюда, верх тела — с
актёра.
