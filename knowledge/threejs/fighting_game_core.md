> 💡 **Интерактивное демо**: `workspace/knowledge-showcase/` (вкладка *«🥊 Файтинг:
> фрейм-дата»*, клавиша <kbd>H</kbd> показывает хитбоксы).
> Головные проверки: `npm run check:fighting` (таблица приёмов) и
> `npm run check:fighting-sim` (прогон живого матча, см. §9).
> Модель бойца и его анимация — `procedural_character_rig.md`;
> физика мира и рэгдолл — `stack/rapier3d.md`.

Эталон для боёв «один на один» (Gladihoppers, Street Fighter-подобные, Toribash-подобные
физические драки). Отличие файтинга от слэшера (`melee_combat_and_ragdoll.md`) — **бой
детерминирован и измеряется в кадрах**, а не в секундах и не в анимационных событиях.
Если игрок не может выучить, что удар бьёт «на 8-м кадре», это не файтинг.

## 0. Фиксированный шаг логики — не опция

Вся боевая логика тикает на **60 логических кадрах в секунду**, независимо от FPS
экрана. Иначе на 144-герцевом мониторе окна парирования становятся в 2.4 раза короче,
а на слабом телефоне — длиннее: одна и та же комбинация проходит или не проходит в
зависимости от устройства.

```typescript
const TICK = 1 / 60;
let acc = 0;

function frame(dt: number): void {
  acc += Math.min(dt, 0.1);
  let steps = 0;
  while (acc >= TICK && steps < 5) { stepLogic(); acc -= TICK; steps++; }
  render(acc / TICK);        // интерполяция визуала между логическими кадрами
}
```

Ввод буферизуется в очередь и **потребляется в `stepLogic()`**, а не читается напрямую
в обработчике: нажатие между тиками не должно теряться.

## 1. Фрейм-дата приёма

Единственная структура, из которой берётся весь баланс. Один приём = четыре числа.

```typescript
export interface Move {
  id: string;
  startup: number;      // кадры до появления хитбокса
  active: number;       // кадры, когда хитбокс живой
  recovery: number;     // кадры бездействия после
  damage: number;
  chip: number;         // урон сквозь блок
  hitstun: number;      // кадры оглушения при попадании
  blockstun: number;    // кадры оглушения при блоке
  hitstop: number;      // кадры заморозки ОБОИХ бойцов при контакте
  pushback: number;     // м/кадр откидывания
  launch: number;       // вертикальный импульс (0 = не подбрасывает)
  advance: number;      // шаг вперёд за время замаха, метры (см. §1.1)
  target: 'head' | 'body';   // зона: от чего защита спасает (см. §1.2)
  hand: 'lead' | 'rear';     // передняя рука быстрее, задняя тяжелее
  stamina: number;      // цена замаха
  guardDamage: number;  // урон по выносливости блокирующего — так ломается гард
  cancelInto: string[]; // во что можно отменить при попадании
  hitbox: BoxSpec;      // локальные координаты относительно бойца
}

export const LIGHT_PUNCH: Move = {
  id: 'lp', startup: 4, active: 3, recovery: 7,
  damage: 40, chip: 4, hitstun: 14, blockstun: 9, hitstop: 6,
  pushback: 0.06, launch: 0, cancelInto: ['mp', 'special_uppercut'],
  hitbox: { x: 0.55, y: 1.25, w: 0.55, h: 0.3, d: 0.4 },
};
```

Ключевые производные величины, которые обязаны считаться, а не подбираться на глаз:

```
frameAdvantage_onBlock = blockstun - (active_remaining + recovery)
frameAdvantage_onHit   = hitstun   - (active_remaining + recovery)
```

* Приём с преимуществом на блоке `> 0` — «безопасный»; таких должно быть 1–2 на бойца.
* Приём с `< -8` наказывается быстрым ударом соперника. Это и есть язык, на котором
  игроки обсуждают файтинг.
* Стартап быстрого удара — 3–5 кадров, среднего — 6–9, тяжёлого — 12–20. Всё, что
  быстрее 3, нечитаемо; медленнее 20 — не попадает никогда.

Баланс живёт в **одном файле данных** (`moves.ts` / `GAME_DATA.yaml`), а не в коде
состояний. Правка урона не должна требовать чтения контроллера.

### 1.1. Досягаемость и шаг вперёд — то, о чём забывают

Дальность приёма **не равна** `hitbox.x`. Считать надо целиком, вместе с шагом
вперёд на замахе и половиной корпуса жертвы:

```typescript
export function reach(move: Move, victimHalfWidth = 0.31): number {
  return move.hitbox.x + move.hitbox.w / 2 + victimHalfWidth + move.advance;
}
```

Эта функция обязана быть **единственным источником дистанции для ИИ**. Ошибка,
которая стоила вкладке всей динамики: бот держал нейтральную дистанцию по
константе `2.2` м, а самый длинный удар в таблице достаёт на `2.13`. Фрейм-дата
корректна, исключений нет, дымовой прогон зелёный — и при этом за 90 секунд
матча не происходит ровно ничего. Ловится только прогоном матча со счётчиком
попаданий (§9).

`advance` (шаг вперёд за кадры замаха) — не украшение. Удар с места достаёт
только того, кто уже стоит вплотную, и нейтраль превращается в переглядывание
на расстоянии вытянутой руки. 0.12–0.3 м на приём: джебу меньше, тяжёлому
больше.

### 1.2. Зоны, защита и выносливость

Три защитных действия и то, от чего каждое спасает:

Каждый приём имеет **уровень**: `low` (по ногам), `mid` (везде), `high` (в голову).

| Действие | high | mid | low | Цена |
|---|---|---|---|---|
| Верхний гард (шаг назад) | блок | блок | блок | выносливость от `guardDamage` |
| Присед | уводит совсем (whiff) | блок | блок | замедление |
| Уклон (слип) | уводит совсем (whiff) | блок | блок | фиксированная выносливость |
| Прыжок | пролетает над | берёт только `hitsAir` | пролетает над | нет блока вообще (§8.1) |

```typescript
export function whiffsAgainst(move: Move, defense: Defense): boolean {
  if (defense === 'air') return !move.hitsAir;      // летящего берёт только анти-эйр
  if (move.height === 'low') return false;          // подсечку не переприседеть
  if (move.height === 'high') return defense === 'crouch' || defense === 'slip';
  return false;                                     // mid не увести — только блокировать
}
```

Уход в молоко (whiff) принципиально отличается от блока: кадры `recovery`
остаются полностью, и промах наказывается. Именно это делает уклон осмысленным
риском, а не бесплатной кнопкой.

**Выносливость** — второй ресурс, без которого файтинг сводится к обмену
ударами до нуля здоровья:

```typescript
export function staminaScale(stamina: number, max: number): number {
  return 0.55 + 0.45 * Math.min(1, Math.max(0, stamina / max));
}
```

* Пустой бак **не отнимает управление** — он режет урон почти вдвое и меняет
  позу (гард опускается). Игрок, у которого забрали кнопки, бросает матч.
* Блок тратит выносливость (`guardDamage`), и на нуле наступает **guard break**:
  длинный стан вместо короткого. Это ответ на «сопернику выгодно блокировать всё».
* Восстанавливается только в нейтрали, и заметно медленнее, чем тратится.

## 2. Машина состояний бойца

```typescript
type FighterState =
  | 'idle' | 'walk' | 'dash' | 'crouch' | 'slip'
  | 'jumpsquat' | 'air' | 'landing'          // прыжок — три состояния, не одно
  | 'startup' | 'active' | 'recovery'
  | 'blockstun' | 'guardbreak' | 'hitstun' | 'airhit'
  | 'knockdown' | 'getup' | 'ko';

class Fighter {
  state: FighterState = 'idle';
  stateFrame = 0;          // сколько кадров в текущем состоянии
  move: Move | null = null;
  hp = 1000;
  meter = 0;               // 0..100, копится за нанесённый и полученный урон
  facing: 1 | -1 = 1;
}
```

Правила, нарушение которых ломает бой:

1. **Отмена (cancel) разрешена только в кадрах `active` и только при подтверждённом
   попадании/блоке.** Отмена «в пустоту» превращает игру в бесконечный мэш кнопок.
2. **`facing` пересчитывается только в `idle`/`walk`/`crouch`.** Разворот в середине
   удара визуально проворачивает хитбокс за спину и рождает «удары назад».
3. **Из `hitstun` нельзя ничего сделать** — ни блок, ни удар. Это и есть комбо.
4. **`wakeup` неуязвим первые 3–5 кадров**, иначе упавшего добивают бесконечно.
5. Приоритет ввода фиксирован: `special > heavy > medium > light`, иначе спецприём
   съедается обычным ударом на том же кадре.

## 3. Хитбоксы и хёртбоксы: AABB, а не меши

Коллизия боя **не** считается по геометрии персонажа. Три набора коробок в локальных
координатах бойца, обновляемые по фрейм-дате:

| Тип | Что | Кому принадлежит |
|---|---|---|
| **hurtbox** | куда можно попасть | всегда активна, меняется по позе (присед — ниже) |
| **hitbox** | чем бьём | живёт только в кадрах `active` |
| **pushbox** | тела не проходят друг сквозь друга | всегда |

```typescript
function worldBox(f: Fighter, b: BoxSpec): THREE.Box3 {
  const cx = f.pos.x + b.x * f.facing, cy = f.pos.y + b.y;
  return new THREE.Box3(
    new THREE.Vector3(cx - b.w / 2, cy - b.h / 2, -b.d / 2),
    new THREE.Vector3(cx + b.w / 2, cy + b.h / 2, b.d / 2),
  );
}

function resolveHits(a: Fighter, d: Fighter): void {
  if (a.state !== 'active' || a.hasHitThisMove) return;
  if (!worldBox(a, a.move!.hitbox).intersectsBox(worldBox(d, d.hurtbox))) return;

  a.hasHitThisMove = true;                     // один удар = одно попадание
  const blocking = d.holdingBack && d.canBlock(a.move!);
  if (blocking) {
    d.hp -= a.move!.chip;
    d.enter('blockstun', a.move!.blockstun);
  } else {
    d.hp -= a.move!.damage * comboScaling(d.comboHits);
    d.enter(a.move!.launch > 0 ? 'launched' : 'hitstun', a.move!.hitstun);
    d.comboHits++;
  }
  applyHitstop(a, d, a.move!.hitstop);
  applyPushback(a, d, a.move!.pushback);
}
```

`hasHitThisMove` сбрасывается при входе в `startup`. Без него мультихит-приём снимает
здоровье каждый кадр активной фазы и убивает с одного удара.

**Затухание комбо** обязательно, иначе любое удачное начало = смерть:

```typescript
const comboScaling = (hits: number) => Math.max(0.25, 1 - hits * 0.09);
```

Визуализация коробок — обязательный дев-инструмент (`Box3Helper` за флагом `?debug=1`).
Файтинг без отладочного отображения хитбоксов не балансируется.

## 4. Hit-stop, откидывание и стены

**Hit-stop** — замирание обоих бойцов на N кадров при контакте. Это главный источник
«веса» удара, и он дешевле любых частиц:

```typescript
if (hitstopFrames > 0) { hitstopFrames--; return; }   // в начале stepLogic
```

Во время hit-stop **визуал продолжает жить**: тряска камеры, вспышка, дрожание модели
на ±2 см. Полная заморозка всего выглядит как лаг.

**Откидывание** двигает бойцов по X, а если защищающийся упёрся в стену — импульс
переходит на атакующего (иначе бойцы «продавливают» арену):

```typescript
const room = arenaHalfWidth - Math.abs(d.pos.x);
const applied = Math.min(pushback, room);
d.pos.x += applied * a.facing;
a.pos.x -= (pushback - applied) * a.facing;    // остаток отдаём атакующему
```

Углы арены — часть геймплея: у стены комбо длиннее, потому что жертва не улетает.
Это должно быть следствием кода, а не отдельной «стеновой» механикой.

## 5. Камера 2.5D

Бой идёт в плоскости `z = 0`; 3D нужно только для читаемости и картинки.

```typescript
const mid = (a.pos.x + b.pos.x) / 2;
const gap = Math.abs(a.pos.x - b.pos.x);
targetX = THREE.MathUtils.clamp(mid, -arenaHalf + 4, arenaHalf - 4);
targetZ = THREE.MathUtils.clamp(6 + gap * 0.55, 7, 16);     // расходятся — камера отъезжает
camera.position.lerp(new THREE.Vector3(targetX, 2.4 + gap * 0.05, targetZ), 1 - Math.exp(-10 * dt));
camera.lookAt(targetX, 1.5, 0);
```

* Камера **никогда** не поворачивается вокруг Y: силуэты должны читаться одинаково всю
  игру. Один взгляд, один язык поз.
* Оба бойца всегда в кадре — это ограничение важнее любой кинематографичности.
* Лёгкий `fov` 40–45 (почти ортография) уплощает сцену и делает дистанцию читаемой;
  широкий fov врёт о расстоянии, и игрок промахивается.

## 6. Управление на телефоне

Классические «мотионы» (`↓↘→ + удар`) на тач-экране не воспроизводятся. Работающая
схема, проверенная на портальных играх:

* Виртуальный стик слева (движение/блок назад/присед), 3–4 кнопки справа.
* Спецприёмы — **отдельные кнопки**, а не мотион-ввод. Мотионы остаются на клавиатуре
  как «продвинутый» ввод и дают тот же приём.
* Буфер ввода — 6 кадров (100 мс): нажатие чуть раньше выхода из `recovery` засчитывается.
  Без буфера комбо на телефоне физически не собирается.
* Кнопки не перекрываются полосами здоровья, инсет по `env(safe-area-inset-*)`
  (`CRITICAL_RULES` §34, §56–59).

## 7. ИИ соперника

Не «сложность = больше здоровья». Бот работает на той же фрейм-дате:

```typescript
// Yuka StateMachine: Neutral -> Approach -> Attack -> Punish -> Retreat
```

* **Реакция.** Бот «видит» приём с задержкой `reactionFrames` (лёгкий 20, средний 12,
  сложный 5). Мгновенная реакция читается игроком как читерство и убивает мотивацию.
* **Наказание.** В `Punish` бот выбирает самый быстрый приём, укладывающийся в
  `frameAdvantage` соперника, — этому его учит та же таблица, что и игрока.
* **Ошибки по расписанию.** У лёгкого бота 25 % шанс пропустить окно наказания.
  Идеальный бот не «сложный», а несправедливый.
* **Neutral-танец.** Шаги вперёд-назад на дистанции чуть больше досягаемости
  (`Yuka ArriveBehavior` с целью «край моей досягаемости») — это и есть «файтинг
  выглядит как файтинг».

Проверка ИИ головная: прогон 1000 матчей бот-против-бота в Node без рендера должен
давать винрейт 45–55 % между равными настройками и разумное распределение длины
матча — это единственный способ поймать «приём X ломает игру» до релиза.

## 8. Воздух: прыжок как решение, а не как перемещение

Файтинг без вертикали — это два бойца на рельсе. Прыжок добавляет второе
измерение решений, но только если он стоит дорого. Работающая раскладка:

**Три состояния вместо одного.** `jumpsquat` (4 кадра приседа) → `air` →
`landing` (6 кадров). Присед — телеграф: соперник должен увидеть прыжок до
взлёта. Приземление — окно наказания: без него прыжок бесплатен, и весь бой
превращается в прыжковую карусель.

```typescript
const GRAVITY = 26;      // м/с², не 9.8: реальная гравитация в файтинге вялая
const JUMP_V = 10.4;     // апекс 2.1 м, полёт ~0.8 с (48 кадров)
const AIR_SPEED = 4.6;   // прыжок вперёд покрывает 3.7 м
```

Числа подбираются от **времени полёта**, а не от высоты: 48 кадров — это
столько, чтобы соперник успел увидеть прыжок и поставить анти-эйр (стартап
9 кадров + реакция 15), но не успел уйти в другой конец ринга.

**Направление фиксируется в приседе и в полёте не меняется.** Управляемый
полёт убивает чтение: прыжок перестаёт быть обязательством.

### 8.1. Кросс-ап: перепрыгнуть соперника

Главная причина, ради которой прыжок существует, — пройти НАД соперником и
приземлиться у него за спиной, развернув ему блок. Технически это одна
строка: выше пояса капсулы перестают видеть друг друга.

```typescript
const passThrough = f.y > CROSS_UP_Y;                       // 0.8 м
if (passThrough !== f.passingThrough) {
  f.passingThrough = passThrough;
  f.collider.setCollisionGroups(passThrough ? FIGHTER_AIR_GROUPS : FIGHTER_GROUPS);
}
```

Два места, и оба обязательны: физическая капсула (иначе прыжок упирается в
невидимую стену ровно там, где начинается самое интересное) **и** логический
pushbox, который разводит бойцов по фрейм-дате. Забыть второй — значит
получить бойца, который визуально пролетел, а логически остался перед
соперником.

`facing` пересчитывается только на земле — поэтому смена стороны происходит
в момент приземления, и это ровно то поведение, которого ждёт игрок.

### 8.2. Что делает воздух честным

* **В воздухе нет блока.** Прыгнул — принял. Это цена входа.
* **Один удар за прыжок** (`airAttackUsed`). Иначе воздух сильнее земли.
* **Обычные приёмы не достают летящего** (`hitsAir: false`), анти-эйр
  (апперкот) достаёт. Прыжок бьётся конкретным ответом, а не любым.
* **Низкий приём (подсечка) под прыжком проходит в молоко** — у прыжка
  появляется собственная защитная функция.
* **Сбитый в воздухе не приземляется на ноги.** `airhit` → приземление →
  нокдаун. Отсюда берётся большая часть рэгдоллов за матч.
* **Жонглирование затухает быстрее обычного комбо** (`1 − juggle * 0.22`,
  пол 0.3), иначе один подброс = вся полоса здоровья.
* **Окно после подъёма** (`KNOCKDOWN_GRACE`, ~70 кадров), в которое сбить с
  ног нельзя — только оглушить. Без него подсечка и нога с воздуха роняют
  бойца бесконечно: он встаёт и тут же ложится обратно.

## 9. Физика: что ей можно отдать, а что нельзя

Файтинг и физический движок уживаются ровно при одном условии: **физика не
принимает ни одного решения о бое**. Граница проходит так.

| Отдаём Rapier | Оставляем целочисленной логике |
|---|---|
| перемещение бойца (стены, канаты, второй боец) | попадания, стан, откидывание, отмены |
| рэгдолл после нокдауна | момент нокдауна |
| реквизит: табурет, ведро, вылетевшая капа, брызги | всё, что влияет на здоровье |

Боец — **кинематическое тело с капсулой** плюс `KinematicCharacterController`:
логика считает желаемое смещение, Rapier отвечает, куда можно.

```typescript
const controller = world.createCharacterController(0.02);   // 0.02 — зазор
controller.setApplyImpulsesToDynamicBodies(true);           // боец пинает реквизит

const desired = { x: (logicX - cur.x) + knockback * TICK, y: dy, z: -cur.z };
controller.computeColliderMovement(collider, desired, undefined, undefined,
  (c) => c !== ownCollider);
const mv = controller.computedMovement();
body.setNextKinematicTranslation({ x: cur.x + mv.x, y: cur.y + mv.y, z: 0 });
logicX = cur.x + mv.x;      // логика принимает то, что РАЗРЕШИЛА физика
```

Ключевая строка — последняя: логическая координата берётся из результата
физики, а не наоборот. Иначе боец «продавливает» канаты в логике, хитбоксы
уезжают за пределы ринга, а картинка с ними расходится.

Три вещи, которые обязательно всплывут:

1. **Зазор контроллера (`offset`) не может быть нулём.** С нулём боец
   вечно в микроконтакте с канатом и дрожит на месте.
2. **Между канатами капсула пролезает.** Видимые канаты — тонкие коллайдеры
   для рэгдолла и реквизита; для бойцов вдоль каждой стороны стоит отдельная
   невидимая стена высотой во весь ринг, в своей группе столкновений.
3. **Pushbox всё равно нужен в логике.** Контроллер разводит капсулы, но
   хитбоксы считаются по плоским коробкам, и расхождение между «капсулой» и
   «коробкой» игрок видит как удары в воздух. Дублирующее разведение по
   `PUSH_WIDTH` после физического шага стоит трёх строк.

Hit-stop замораживает **и физику тоже** (`world.step()` не вызывается): иначе
в кадре веса удара замирают бойцы, а реквизит и брызги продолжают ехать.

Рэгдолл на нокдауне собирается из настоящих мешей персонажа, а не из
капсул-заменителей — двое бойцов крупным планом, подмена видна сразу. Механика
передачи подграфов рига в физику и возврата обратно — в
`procedural_character_rig.md` §5.

## 10. Прогон живого матча — отдельная проверка

Проверка таблицы приёмов и дымовой прогон демо **не пересекаются** с вопросом
«а бой-то идёт?». Нужна третья, головная, без рендера:

```
Матч 90 секунд:
  попаданий: 77 · нокдаунов: 10 · тиков в рэгдолле: 970
  прыжки: высота 2.09 м · ударов с воздуха 203 · перепрыгиваний 3 · кадров подъёма 320
  ok   бой идёт: больше 40 попаданий за 90 секунд
  ok   бот не машет из-за пределов досягаемости
  ok   за матч случился хотя бы один нокдаун
  ok   рэгдолл действительно падает (голова ниже 0.6 м)
  ok   через соперника можно перепрыгнуть
  ok   подъём начинается с настила и заканчивается в стойке
  ok   физические тела не копятся
```

Что она обязана мерить:

* **Попаданий за матч.** Ноль попаданий при зелёной фрейм-дате — самый дорогой
  и самый незаметный баг в жанре.
* **Дистанцию, с которой бот начинает приём.** Больше `reach()` — значит ИИ
  живёт в своей системе координат.
* **Нокдаун и рэгдолл.** Голова упавшего должна оказаться ниже таза: это
  дешёвая проверка того, что физика вообще подхватила персонажа.
* **Утечки тел.** Количество rigid body после матча — как до него. Вылетевшие
  капы, брызги и кости рэгдолла обязаны убираться на сбросе раунда.
* **Границы ринга.** `|x| < половины ринга` для обоих в конце прогона.
* **Воздух.** Высота прыжка, число ударов с воздуха и — главное — сколько раз
  бойцы поменялись сторонами, находясь в воздухе. Кросс-ап ломается от любой
  правки групп столкновений и не виден ни в одной другой проверке.
* **Подъём.** Высота головы в первом и последнем кадре `getup`: с настила
  (< 1.1 м) в стойку (> 1.5 м). Так ловится «боец телепортируется из
  рэгдолла в стойку», которое выглядит как сломанная физика.

Считать тела на утечки надо **после** того, как последний упавший встал:
восемь костей активного рэгдолла иначе читаются как утечка.

Прогон 1000 матчей бот-против-бота с винрейтом 45–55 % (§7) — следующий шаг,
но начинается всё с одного матча, в котором вообще что-то происходит.

## 11. Чек-лист качества

* [ ] Логика на фиксированных 60 тиках, визуал интерполируется.
* [ ] Вся фрейм-дата в одном файле данных; в коде состояний нет чисел урона.
* [ ] Hit-stop, откидывание и затухание комбо реализованы.
* [ ] Отладочная визуализация hitbox/hurtbox/pushbox по флагу.
* [ ] Один удар наносит один хит; `hasHitThisMove` сбрасывается в `startup`.
* [ ] `wakeup` даёт кадры неуязвимости.
* [ ] Оба бойца всегда в кадре, камера не вращается.
* [ ] Буфер ввода 6 кадров; спецприёмы имеют кнопочный ввод для телефона.
* [ ] Бот реагирует с задержкой и ошибается по расписанию.
* [ ] Дистанции ИИ считаются через `reach()`, а не константами.
* [ ] У каждого приёма есть `advance`: удар входит в дистанцию.
* [ ] Зоны (голова/корпус) и три защитных действия; whiff отличается от блока.
* [ ] Выносливость режет урон, но не отнимает управление; есть guard break.
* [ ] Физике отдано перемещение и рэгдолл, но ни одно решение о бое.
* [ ] Hit-stop останавливает и `world.step()`.
* [ ] Прыжок — три состояния (присед, полёт, приземление), направление
      фиксируется в приседе, в воздухе нет блока и есть один удар.
* [ ] Кросс-ап работает и в физике, и в логическом pushbox; `facing`
      пересчитывается только на земле.
* [ ] Есть анти-эйр, и обычные приёмы летящего не достают.
* [ ] Сбитый в воздухе приземляется нокдауном; жонглирование затухает.
* [ ] После подъёма есть окно, в которое нельзя снова сбить с ног.
* [ ] Подъём с настила — отдельная фаза с анимацией, а не мгновенный сброс позы.
* [ ] Прогон живого матча в CI: попадания, нокдаун, кросс-ап, подъём,
      отсутствие утечек тел.
* [ ] Головной прогон 1000 матчей: винрейт 45–55 %.
