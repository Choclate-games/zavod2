# Процедурный персонаж-человек на Three.js: риг, поза, износ, рэгдолл

> 💡 **Интерактивное демо**: `workspace/knowledge-showcase/` (вкладка *«🥊 Файтинг:
> фрейм-дата»*). Код: `src/world/boxerRig.ts` (риг), `src/world/boxerRagdoll.ts`
> (передача в физику), `src/demos/FightingDemo.ts` → `poseRig()` (анимация).

`procedural_mesh_builder.md` отвечает на вопрос «как собрать модель из боксов».
Этот файл — о том, **почему одна коробочная модель читается как человек, а
другая как стопка кубиков**, и как анимировать её без единого `.glb`.

Источник подхода — проект **PunchBox** (`Boxer.js`, боксёрская игра на Three.js
без единой внешней модели) и вкладка файтинга в стенде. Камера там смотрит
бойцам в лицо метра с трёх — дистанция, на которой любая экономия на риге видна
сразу.

---

## 0. Когда процедурный персонаж — правильный выбор

* Персонажей 1–4 в кадре, они крупные, и их надо кастомизировать (цвет, лицо,
  телосложение). Модели-«скины» на каждый вариант не окупятся.
* Портальная игра, где вес билда важнее фотореализма: риг из 40 боксов — это
  ноль байт загрузки и ноль времени на импорт.
* Нужен рэгдолл из тех же мешей, что и живой персонаж (см. §5).

Если персонажей десятки и они мелкие — берите инстансированные капсулы, а не
это. Риг ниже стоит ~40 draw-примитивов на бойца без батчинга.

## 1. Иерархия: где ставить группы, а где меши

Правило одно: **одна степень свободы — одна группа**. Object3D с
`Euler('XYZ')`, которому крутят сразу две оси, визуально скручивает конечность
(`CRITICAL_RULES` §55).

```
root                       // мировая позиция, разворот к сопернику
├── hips                   // таз: сюда подсед и ходьба
│   ├── thighL ── shinL ── (ботинок, подошва)
│   └── thighR ── shinR
└── body                   // корень корпуса: наклоны, уклоны, «вес» позы
    └── waist              // НИЖНИЙ сегмент спины (пресс, трусы, пояс)
        └── chest          // ВЕРХНИЙ сегмент спины (грудь, плечевой пояс)
            ├── head       // череп + лицо + волосы
            ├── shoulderL ── elbowL ── (предплечье, бинт, перчатка)
            └── shoulderR ── elbowR
```

Три решения, которые здесь неочевидны и каждое стоило переделки:

**Позвоночник из двух сегментов (`waist` → `chest`).** Один торс-кубик не
умеет уклоняться. Уклон — это наклон таза в одну сторону и доворот плеч в
другую; с одним сегментом получается падающая доска, а не боксёр.

**Таз и корпус — два разных корня, оба от `root`.** Ноги не должны наследовать
наклон корпуса: боец уклоняется верхом, а стоит на месте. Если повесить ноги
на `chest`, при уклоне ступни уезжают из-под бойца.

**Разворот к сопернику — ±90°, а не ±180°.** Модель смотрит в `+Z`, соперник
стоит по оси X. Поворот на π (привычный «flip» из 2D-файтингов) показывает
камере спину, и весь бой смотрится в затылок. Правильный разворот —
`facing * (π/2 − 0.32)`: боец в профиль, но чуть открыт зрителю.

```typescript
export function boxerYaw(facing: 1 | -1): number {
  return facing * (Math.PI / 2 - 0.32);   // 0.32 рад — полубоковая стойка
}
```

Если стойка (полубоковой доворот) зашита в сам риг, а не в `root`, она не
зеркалится: у бойца, смотрящего влево, плечо ведёт не в ту сторону. Всё, что
зависит от `facing`, живёт в `root`.

## 2. Что именно делает модель «человеком»

Порядок по отдаче на потраченный бокс:

1. **Шея.** Голова, приклеенная к груди, — главный признак самоделки.
   Один кубик 0.13 м между ними чинит силуэт.
2. **Плечевой пояс (`yoke`) шире груди на 8–10 %, не больше.** На 20 % это
   уже доска, торчащая из спины: проверяется только в профиль.
3. **Нос глубиной 0.07–0.08 м.** Персонаж, стоящий боком, читается по носу и
   подбородку. Плоское лицо в профиль — это овал.
4. **Сустав между сегментами конечности** (кубик локтя/колена чуть толще
   самой конечности). Без него рука на сгибе разваливается на два бруска.
5. **Одна «фирменная» деталь профессии.** У боксёра — капа и бинты, у
   рабочего — каска. Она делает силуэт узнаваемым раньше, чем лицо.
6. **Обувь выше щиколотки.** Низкий ботинок в силуэте читается как обрубок
   ноги; голенище 0.24 м с выступающей вперёд подошвой — как обувь.

Материал: `flatShading: true` на коже и одежде. Плоские грани дают жёсткие
переходы, из-за которых кубическая модель выглядит намеренно стилизованной, а
не бедной.

## 3. Лицо по seed: ростер без ручной работы

Черты выбирает крошечный LCG, засеянный индексом бойца. Тот же индекс — то же
лицо всегда: ростер воспроизводим, сейв хранит одно число, а не описание лица.

```typescript
function faceTraits(index: number) {
  let s = ((index + 1) * 1103515245 + 12345) % 2147483647;
  const rnd = () => (s = (s * 48271) % 2147483647) / 2147483647;
  return {
    eyeW: 0.045 + rnd() * 0.025,
    eyeGap: 0.055 + rnd() * 0.02,
    browAngle: (rnd() - 0.35) * 0.5,   // сдвиг: злых лиц больше, чем удивлённых
    noseW: 0.04 + rnd() * 0.03,
    jaw: rnd() > 0.55,
  };
}
```

`Math.random()` здесь — ошибка: лицо соперника меняется при каждом рестарте
раунда, и игрок перестаёт узнавать противника.

Смещение в `browAngle` — не косметика: диапазон, симметричный вокруг нуля,
даёт половину ростера с «домиком» бровей, и все выглядят напуганными.

## 4. Износ: модель рассказывает историю боя

Полоса здоровья говорит число. Синяк говорит, **куда** били.

Каждая накладка — плоскость с `transparent: true, opacity: 0`, приклеенная
чуть впереди грани родителя, с порогом по накопленному урону **в своей зоне**:

```typescript
setDamage(headDmg: number, bodyDmg: number) {
  for (const d of decals) {
    const wear = d.zone === 'head' ? headDmg : bodyDmg;
    const t = THREE.MathUtils.clamp((wear - d.threshold) / 0.25, 0, 1);
    d.mesh.visible = t > 0.02;                 // невидимое не рисуем
    d.mesh.material.opacity = t * d.maxOpacity;
  }
}
```

* Зоны раздельные: боец, которого били по корпусу, остаётся с чистым лицом.
  Общий счётчик урона убивает весь смысл механики.
* `depthWrite: false` и `renderOrder = 2`, иначе накладка мерцает с гранью,
  на которой лежит.
* `visible = false` при нулевой прозрачности: прозрачные плоскости всё равно
  идут в проход сортировки и стоят кадра.

## 5. Передача персонажа физике: рэгдолл из НАСТОЯЩИХ мешей

Классический рэгдолл (`mechanics/ragdoll.md`, `world/ragdoll.ts`) прячет
живую модель и показывает семь капсул. Для толпы врагов это правильно и
дёшево. Для персонажа, которого камера показывает крупно, подмена видна в
первом же кадре падения.

Приём: физике отдаются **подграфы самого рига**.

```typescript
box.setFromObject(bone.object);      // мировой AABB подграфа
box.getCenter(center); box.getSize(size);

const body = world.createRigidBody(
  RAPIER.RigidBodyDesc.dynamic().setTranslation(center.x, center.y, center.z)
    .setLinearDamping(0.2).setAngularDamping(3.5).setCcdEnabled(true),
);
world.createCollider(
  RAPIER.ColliderDesc.cuboid(size.x / 2, size.y / 2, size.z / 2)
    .setMass(bone.mass).setCollisionGroups(RAGDOLL_GROUPS), body);

const holder = new THREE.Group();
holder.position.copy(center);
scene.add(holder);
holder.attach(bone.object);          // attach, НЕ add: сохраняет мировой трансформ
```

Что здесь легко сломать:

1. **Порядок костей — «листья → корень».** `Box3.setFromObject(chest)`, пока
   голова и руки ещё дети груди, вернёт габарит всего торса с головой. Сначала
   отцепляем голову, руки и бёдра, потом считаем грудь.
2. **`attach`, а не `add`.** `add` роняет подграф в локальные координаты нового
   родителя — персонаж собирается в точку.
3. **Возврат в иерархию требует снимка.** После рэгдолла `parent.add(object)`
   вернёт объект с матрицей от holder-группы. Локальные позиции/кватернионы
   всех костей снимаются один раз при сборке рига и восстанавливаются на
   вставании (`resetPose`).
4. **Минимальная полутолщина коллайдера.** У плоских деталей (накладки урона,
   бинты) AABB почти нулевой, и Rapier делает вырожденный кубоид.
5. Три классические ловушки рэгдолла остаются в силе: части одного тела не
   сталкиваются друг с другом (группы столкновений), угловое демпфирование
   обязательно, импульс — один раз и с потолком.

Обратный переход (боец встаёт) берёт X у таза рэгдолла: иначе персонаж
телепортируется туда, где стоял до падения.

**И это ещё не всё — подъём обязан быть фазой, а не сбросом позы.** Самая
частая поломка выглядит так: рэгдолл выключили, `resetPose` поставил стойку,
и персонаж мгновенно оказался стоящим там, где секунду назад лежал. Со
стороны это читается как «физика сломалась». Лечится двумя вещами:

1. **Первый кадр после рэгдолла ставится без интерполяции** — иначе поза
   «доезжает» в лежачее положение из стойки предыдущего кадра:

   ```typescript
   const k = f.poseSnap ? 1 : 1 - Math.exp(-16 * dt);
   f.poseSnap = false;      // взводится один раз, в момент выключения рэгдолла
   ```

2. **Отдельное состояние подъёма** (~40 кадров) с позой, ведомой прогрессом:
   боец начинает лёжа (корпус наклонён на 1.35 рад, таз у настила, колени
   сложены) и распрямляется к концу. Проверяется головно — высотой головы в
   первом и последнем кадре фазы.

## 6. Анимация без клипов: «цель + приближение»

Ни одного `AnimationMixer`. Каждое состояние объявляет, **куда** должны
приехать плечи, локти, корпус, голова и таз; кадр рендера доезжает туда
экспоненциально с одним общим коэффициентом:

```typescript
const k = 1 - Math.exp(-16 * dt);        // один k на всё тело
rig.body.rotation.x += (targetBodyRotX - rig.body.rotation.x) * k;
lerpEuler(rig.shoulderL.rotation, targetShoulderL, k);
// ...
```

* **Один коэффициент на весь риг.** Разные скорости у разных конечностей
  визуально «разваливают» позу: тело уже в новой стойке, рука ещё в старой.
* **Переход из любого состояния в любое получается бесплатно.** Это главное
  преимущество перед клипами: не нужны ни blend-деревья, ни таблица
  переходов, а прерывание анимации ударом выглядит естественно.
* **Всегда есть покачивание.** Даже в `idle` корпус ведёт синусоидой по трём
  осям с разными периодами. Персонаж, стоящий абсолютно неподвижно хотя бы
  один кадр, выглядит сломанным.
* **Усталость меняет позу, а не только полосу.** Гард опускается, корпус
  наклоняется — состояние ресурса видно по силуэту.

Дуга удара берётся **из фрейм-даты**, а не из клипа: замах длится ровно
`startup` кадров, выпад — `active`, возврат — `recovery`.

```typescript
if (elapsed <= startup) {
  extend = -0.22 * Math.sin((elapsed / startup) * Math.PI / 2);   // замах НАЗАД
} else if (elapsed <= startup + active) {
  const p = (elapsed - startup) / active;
  extend = -0.22 + 1.32 * Math.sin(p * Math.PI / 2);              // выпад с перелётом
} else {
  extend = 1.1 * (1 - (elapsed - startup - active) / recovery);   // возврат
}
```

Отрицательная фаза замаха обязательна: без неё удар не читается по кадрам, и
игрок не может научиться реагировать. Правка числа в таблице приёмов
автоматически меняет анимацию — рассинхрона «анимация против хитбокса»
не существует по построению.

**Squash & stretch** добавляется поверх: перчатка на выпаде растягивается до
1.28, грудь на замахе — до 1.14 по Z, и обе возвращаются к 1 с отдельным,
более медленным коэффициентом.

## 7. Чек-лист

* [ ] Позвоночник из двух сегментов; таз и корпус — независимые корни.
* [ ] Каждая степень свободы — своя группа (плечо → локоть → предплечье).
* [ ] Разворот к цели через `root`, ±90° для боковой камеры, и он зеркалится.
* [ ] Есть шея, нос глубиной ≥ 0.07, суставы на сгибах, обувь выше щиколотки.
* [ ] Лицо и телосложение — от seed, не от `Math.random()`.
* [ ] Износ по зонам, накладки с `depthWrite: false` и `visible = false` при нуле.
* [ ] Рэгдолл использует меши персонажа; кости считаются «листья → корень»;
      `attach`, а не `add`; снимок локальных трансформов для возврата.
* [ ] Анимация — цели + один коэффициент приближения; дуга удара выводится
      из фрейм-даты; в `idle` персонаж никогда не стоит неподвижно.
