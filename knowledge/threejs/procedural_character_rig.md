# Процедурный персонаж-человек на Three.js: риг, поза, износ, рэгдолл

> 💡 **Интерактивное демо**: `workspace/knowledge-showcase/` (вкладка *«🥊 Файтинг:
> фрейм-дата»*). Код: `src/world/boxerRig.ts` (риг), `src/world/boxerRagdoll.ts`
> (передача в физику), `src/demos/FightingDemo.ts` → `poseRig()` (анимация).
>
> ⚠️ В кадре демо сейчас **готовые модели** (X Bot и Y Bot из `assets/`), а риг
> из этого файла — запасной путь, если FBX не загрузился. Анимация у них общая:
> как надеть её на чужой скелет — `skinned_character_models.md` §4.

`procedural_mesh_builder.md` отвечает на вопрос «как собрать модель из боксов».
Этот файл — о том, **почему одна коробочная модель читается как человек, а
другая как стопка кубиков**, и как анимировать её без единого `.glb`.

Источник подхода — проект **PunchBox** (`Boxer.js`, боксёрская игра на Three.js
без единой внешней модели) и вкладка файтинга в стенде. Камера там смотрит
бойцам в лицо метра с трёх — дистанция, на которой любая экономия на риге видна
сразу.

## 0. Когда процедурный персонаж — правильный выбор

* Персонажей 1–4 в кадре, они крупные, и их надо кастомизировать (цвет, лицо,
  телосложение). Модели-«скины» на каждый вариант не окупятся.
* Портальная игра, где вес билда важнее фотореализма: риг из 40 боксов — это
  ноль байт загрузки и ноль времени на импорт.
* Нужен рэгдолл из тех же мешей, что и живой персонаж (см. §5).

Если модель уже есть (`assets/`, Mixamo, любой FBX) — берите её, а этот файл
читайте с §6: поза-цель и дуга удара из фрейм-даты не зависят от того, из чего
собран персонаж. Сравнение двух путей — `skinned_character_models.md` §0.

Если персонажей десятки и они мелкие — берите инстансированные капсулы, а не
это. Риг ниже стоит ~40 draw-примитивов на бойца без батчинга.

## 1. Иерархия: где ставить группы, а где меши

Правило одно: **одна степень свободы — одна группа**. Object3D с
`Euler('XYZ')`, которому крутят сразу две оси, визуально скручивает конечность
(`CRITICAL_RULES` §55).

```
root                       // мировая позиция, разворот к сопернику
├── hips                   // таз: сюда подсед и ходьба
│   ├── thighL ── shinL ── (ботинок, подошва)
│   └── thighR ── shinR
└── body                   // корень корпуса: наклоны, уклоны, «вес» позы
    └── waist              // НИЖНИЙ сегмент спины (пресс, трусы, пояс)
        └── chest          // ВЕРХНИЙ сегмент спины (грудь, плечевой пояс)
            ├── head       // череп + лицо + волосы
            ├── shoulderL ── elbowL ── (предплечье, бинт, перчатка)
            └── shoulderR ── elbowR
```

Три решения, которые здесь неочевидны и каждое стоило переделки:

**Позвоночник из двух сегментов (`waist` → `chest`).** Один торс-кубик не
умеет уклоняться. Уклон — это наклон таза в одну сторону и доворот плеч в
другую; с одним сегментом получается падающая доска, а не боксёр.

**Таз и корпус — два разных корня, оба от `root`.** Ноги не должны наследовать
наклон корпуса: боец уклоняется верхом, а стоит на месте. Если повесить ноги
на `chest`, при уклоне ступни уезжают из-под бойца.

**Разворот к сопернику — ±90°, а не ±180°.** Модель смотрит в `+Z`, соперник
стоит по оси X. Поворот на π (привычный «flip» из 2D-файтингов) показывает
камере спину, и весь бой смотрится в затылок. Правильный разворот —
`facing * (π/2 − 0.32)`: боец в профиль, но чуть открыт зрителю.

```typescript
export function boxerYaw(facing: 1 | -1): number {
  return facing * (Math.PI / 2 - 0.32);   // 0.32 рад — полубоковая стойка
}
```

Если стойка (полубоковой доворот) зашита в сам риг, а не в `root`, она не
зеркалится: у бойца, смотрящего влево, плечо ведёт не в ту сторону. Всё, что
зависит от `facing`, живёт в `root`.

## 2. Что именно делает модель «человеком»

Порядок по отдаче на потраченный бокс:

1. **Шея.** Голова, приклеенная к груди, — главный признак самоделки.
   Один кубик 0.13 м между ними чинит силуэт.
2. **Плечевой пояс (`yoke`) шире груди на 8–10 %, не больше.** На 20 % это
   уже доска, торчащая из спины: проверяется только в профиль.
3. **Нос глубиной 0.07–0.08 м.** Персонаж, стоящий боком, читается по носу и
   подбородку. Плоское лицо в профиль — это овал.
4. **Сустав между сегментами конечности** (кубик локтя/колена чуть толще
   самой конечности). Без него рука на сгибе разваливается на два бруска.
5. **Одна «фирменная» деталь профессии.** У боксёра — капа и бинты, у
   рабочего — каска. Она делает силуэт узнаваемым раньше, чем лицо.
6. **Обувь выше щиколотки.** Низкий ботинок в силуэте читается как обрубок
   ноги; голенище 0.24 м с выступающей вперёд подошвой — как обувь.

Материал: `flatShading: true` на коже и одежде. Плоские грани дают жёсткие
переходы, из-за которых кубическая модель выглядит намеренно стилизованной, а
не бедной.

## 3. Лицо по seed: ростер без ручной работы

Черты выбирает крошечный LCG, засеянный индексом бойца. Тот же индекс — то же
лицо всегда: ростер воспроизводим, сейв хранит одно число, а не описание лица.

```typescript
function faceTraits(index: number) {
  let s = ((index + 1) * 1103515245 + 12345) % 2147483647;
  const rnd = () => (s = (s * 48271) % 2147483647) / 2147483647;
  return {
    eyeW: 0.045 + rnd() * 0.025,
    eyeGap: 0.055 + rnd() * 0.02,
    browAngle: (rnd() - 0.35) * 0.5,   // сдвиг: злых лиц больше, чем удивлённых
    noseW: 0.04 + rnd() * 0.03,
    jaw: rnd() > 0.55,
  };
}
```

`Math.random()` здесь — ошибка: лицо соперника меняется при каждом рестарте
раунда, и игрок перестаёт узнавать противника.

Смещение в `browAngle` — не косметика: диапазон, симметричный вокруг нуля,
даёт половину ростера с «домиком» бровей, и все выглядят напуганными.

## 4. Износ: модель рассказывает историю боя

Полоса здоровья говорит число. Синяк говорит, **куда** били.

Каждая накладка — плоскость с `transparent: true, opacity: 0`, приклеенная
чуть впереди грани родителя, с порогом по накопленному урону **в своей зоне**:

```typescript
setDamage(headDmg: number, bodyDmg: number) {
  for (const d of decals) {
    const wear = d.zone === 'head' ? headDmg : bodyDmg;
    const t = THREE.MathUtils.clamp((wear - d.threshold) / 0.25, 0, 1);
    d.mesh.visible = t > 0.02;                 // невидимое не рисуем
    d.mesh.material.opacity = t * d.maxOpacity;
  }
}
```

* Зоны раздельные: боец, которого били по корпусу, остаётся с чистым лицом.
  Общий счётчик урона убивает весь смысл механики.
* `depthWrite: false` и `renderOrder = 2`, иначе накладка мерцает с гранью,
  на которой лежит.
* `visible = false` при нулевой прозрачности: прозрачные плоскости всё равно
  идут в проход сортировки и стоят кадра.

## 5. Передача персонажа физике: рэгдолл из НАСТОЯЩИХ мешей

Классический рэгдолл (`mechanics/ragdoll.md`, `world/ragdoll.ts`) прячет
живую модель и показывает семь капсул. Для толпы врагов это правильно и
дёшево. Для персонажа, которого камера показывает крупно, подмена видна в
первом же кадре падения.

Приём: физике отдаются **подграфы самого рига**.

```typescript
box.setFromObject(bone.object);      // мировой AABB подграфа
box.getCenter(center); box.getSize(size);

const body = world.createRigidBody(
  RAPIER.RigidBodyDesc.dynamic().setTranslation(center.x, center.y, center.z)
    .setLinearDamping(0.2).setAngularDamping(3.5).setCcdEnabled(true),
);
world.createCollider(
  RAPIER.ColliderDesc.cuboid(size.x / 2, size.y / 2, size.z / 2)
    .setMass(bone.mass).setCollisionGroups(RAGDOLL_GROUPS), body);

const holder = new THREE.Group();
holder.position.copy(center);
scene.add(holder);
holder.attach(bone.object);          // attach, НЕ add: сохраняет мировой трансформ
```

Что здесь легко сломать:

1. **Порядок костей — «листья → корень».** `Box3.setFromObject(chest)`, пока
   голова и руки ещё дети груди, вернёт габарит всего торса с головой. Сначала
   отцепляем голову, руки и бёдра, потом считаем грудь.
2. **`attach`, а не `add`.** `add` роняет подграф в локальные координаты нового
   родителя — персонаж собирается в точку.
3. **Возврат в иерархию требует снимка.** После рэгдолла `parent.add(object)`
   вернёт объект с матрицей от holder-группы. Локальные позиции/кватернионы
   всех костей снимаются один раз при сборке рига и восстанавливаются на
   вставании (`resetPose`).
4. **Минимальная полутолщина коллайдера.** У плоских деталей (накладки урона,
   бинты) AABB почти нулевой, и Rapier делает вырожденный кубоид. У скиненной
   модели AABB кости пустой всегда (геометрии в подграфе нет) — там габариты
   приходят отдельным полем, `skinned_character_models.md` §5.
5. **Сшивать суставами — ВТОРЫМ проходом.** Это прямое следствие пункта 1 и
   ловушка, которую видно только в кадре. Кость ссылается на родителя, а
   порядок «листья → корень» означает, что родитель в этот момент ещё не
   создан: `parts.get(bone.parent)` возвращает `undefined`, и связь тихо не
   создаётся. Никакого исключения — просто у трупа из восьми тел три сустава
   вместо семи. У нас так остались несвязанными обе руки и обе ноги: корпус
   падал, а ноги стояли на настиле, потому что их коробки опираются на пол и
   тянуть их было нечем. Поэтому: сначала цикл, создающий все тела, затем
   отдельный цикл `for (const bone of bones) link(bone)`. И проверяйте число
   связей явно — их всегда на одну меньше, чем тел.
6. Три классические ловушки рэгдолла остаются в силе: части одного тела не
   сталкиваются друг с другом (группы столкновений), угловое демпфирование
   обязательно, импульс — один раз и с потолком.

**И всё это ещё не даёт похожего на человека падения.** Сшитый по всем
правилам рэгдолл из восьми тел оседал вертикально вниз и превращался в
комок на месте, где боец стоял. Четыре вещи, которые пришлось сделать
отдельно, — и все четыре измеримы:

* **Разбить конечности по суставам.** Рука одним телом от плеча до перчатки
  не гнётся нигде; восемь тел выглядят манекеном из палок. Двенадцать:
  голова, три сегмента корпуса, по два на руку и на ногу.
* **Колено и локоть — шарнир с пределами.** Ось шарнира — боковая ось
  персонажа, а пределы отсчитываются от позы В МОМЕНТ НОКДАУНА: тела
  создаются без поворота, поэтому угол сустава на старте равен нулю
  независимо от позы, и анатомический ноль — это «минус текущий сгиб».
  Отдельная засада: `limitsEnabled`/`limits` в дескрипторе Rapier молча не
  применяются, работает только `joint.setLimits()` после создания.
* **Тонус позвоночника.** Моторов у шарового сустава в этой сборке Rapier
  нет (типы обещают, `createImpulseJoint` возвращает объект без них — падение
  в рантайме). Заменяются пружинами `JointData.spring` через сустав, с длиной
  покоя «как сейчас»: голова↔пояс и грудь↔таз на позвоночник, бедро↔грудь,
  голень↔таз и плечо↔таз на конечности — восемь связок на двенадцать тел.
* **Бросать тело целиком.** Стартовая скорость задаётся всем частям как
  одному твёрдому телу: `v = v_цм + ω × (r − r_цм)`, где `ω = вверх × полёт`
  — с этим знаком боец падает на спину, с обратным ныряет лицом вперёд и
  садится на колени. И угловое демпфирование из пункта 6 придётся снизить:
  полный оборот равен ω/λ, при λ = 3.5 это 50° — лечь не хватает.

Подробности и числа — `mechanics/ragdoll.md`, раздел «Почему рэгдолл
выглядит кучей тряпья».

Обратный переход (боец встаёт) берёт X у таза рэгдолла: иначе персонаж
телепортируется туда, где стоял до падения.

**И это ещё не всё — подъём обязан быть фазой, а не сбросом позы.** Самая
частая поломка выглядит так: рэгдолл выключили, `resetPose` поставил стойку,
и персонаж мгновенно оказался стоящим там, где секунду назад лежал. Со
стороны это читается как «физика сломалась». Лечится двумя вещами:

1. **Первый кадр после рэгдолла ставится без интерполяции** — иначе поза
   «доезжает» в лежачее положение из стойки предыдущего кадра:

   ```typescript
   const k = f.poseSnap ? 1 : 1 - Math.exp(-16 * dt);
   f.poseSnap = false;      // взводится один раз, в момент выключения рэгдолла
   ```

2. **Отдельное состояние подъёма** (~40 кадров) с позой, ведомой прогрессом:
   боец начинает лёжа (корпус наклонён на 1.35 рад, таз у настила, колени
   сложены) и распрямляется к концу. Проверяется головно — высотой головы в
   первом и последнем кадре фазы.

## 6. Анимация без клипов: «цель + приближение»

Ни одного `AnimationMixer`. Каждое состояние объявляет, **куда** должны
приехать плечи, локти, корпус, голова и таз; кадр рендера доезжает туда
экспоненциально с одним общим коэффициентом:

```typescript
const k = 1 - Math.exp(-16 * dt);        // один k на всё тело
rig.body.rotation.x += (targetBodyRotX - rig.body.rotation.x) * k;
lerpEuler(rig.shoulderL.rotation, targetShoulderL, k);
// ...
```

* **Один коэффициент на весь риг.** Разные скорости у разных конечностей
  визуально «разваливают» позу: тело уже в новой стойке, рука ещё в старой.
* **Переход из любого состояния в любое получается бесплатно.** Это главное
  преимущество перед клипами: не нужны ни blend-деревья, ни таблица
  переходов, а прерывание анимации ударом выглядит естественно.
* **Всегда есть покачивание.** Даже в `idle` корпус ведёт синусоидой по трём
  осям с разными периодами. Персонаж, стоящий абсолютно неподвижно хотя бы
  один кадр, выглядит сломанным.
* **Усталость меняет позу, а не только полосу.** Гард опускается, корпус
  наклоняется — состояние ресурса видно по силуэту.

Дуга удара берётся **из фрейм-даты**, а не из клипа: замах длится ровно
`startup` кадров, выпад — `active`, возврат — `recovery`.

```typescript
if (elapsed <= startup) {
  extend = -0.22 * Math.sin((elapsed / startup) * Math.PI / 2);   // замах НАЗАД
} else if (elapsed <= startup + active) {
  const p = (elapsed - startup) / active;
  extend = -0.22 + 1.32 * Math.sin(p * Math.PI / 2);              // выпад с перелётом
} else {
  extend = 1.1 * (1 - (elapsed - startup - active) / recovery);   // возврат
}
```

Отрицательная фаза замаха обязательна: без неё удар не читается по кадрам, и
игрок не может научиться реагировать. Правка числа в таблице приёмов
автоматически меняет анимацию — рассинхрона «анимация против хитбокса»
не существует по построению.

**Squash & stretch** добавляется поверх: перчатка на выпаде растягивается до
1.28, грудь на замахе — до 1.14 по Z, и обе возвращаются к 1 с отдельным,
более медленным коэффициентом.

### Знак поворота ноги: колено гнётся в одну сторону

Самая дорогая ошибка этого раздела — не в позах, а в знаке. Конечность в
покое смотрит вниз (−Y), персонаж смотрит вперёд (+Z). Поворот вокруг **+X**
тянет −Y к −Z, то есть **уводит ногу назад**:

```
Rx(θ)·(0,−1,0) = (0, −cos θ, −sin θ)      θ > 0  →  z < 0  →  назад
```

Значит физически верно так: **у бедра «колено вперёд» — это минус**, а
**у голени «пятка к ягодице» — это плюс**. Интуиция подсказывает обратное,
и почти наверняка позы вы напишете в человеческом смысле («присед: бедро
+1.05, голень −1.5»). Тогда инвертируйте один раз на применении:

```typescript
lerpAxes(rig.thighL.rotation, -thighL, 0, 0, k);
lerpAxes(rig.shinL.rotation,  -shinL,  0, 0, k);
```

Почему это стоит отдельного абзаца: с перепутанным знаком поза остаётся
похожей на правильную. Присед всё так же приседает, прыжок поджимает ноги,
подсечка выносит ногу — потому что бедро и голень скомпенсировали друг
друга. Неверно только **колено**: оно уходит за спину. На риге из коробок
это выглядит как «странная походка», на скиненной модели — как сломанные
ноги. У нас так жили девять анимаций из двадцати, и ни один замер их не
видел: высота головы, размах стопы, вынос перчатки, глубина приседа — всё
сходилось.

Ловится это ровно одним числом — **выносом колена вперёд от прямой
«тазобедренный сустав → лодыжка»**. У человека он всегда положительный:

```typescript
// в системе координат персонажа, плоскость (z, y)
const uz = ankle.z - hip.z, uy = ankle.y - hip.y;
const len = Math.hypot(uz, uy);
if (len < 0.3) return 0;                  // нога сложена — вопрос без смысла
return (uz / len) * (knee.y - hip.y) - (uy / len) * (knee.z - hip.z);
```

Через разность высот (`t = (knee.y − hip.y) / (ankle.y − hip.y)`) считать
нельзя: в подъёме с настила лодыжка оказывается на высоте таза, знаменатель
уходит в ноль и замер выдаёт минус пятнадцать метров.

### Удар ногой: три фазы, а не одна дуга

Первое, что хочется написать для удара ногой, — полуволна синуса на всю
длительность приёма: бедро поднимается, голень выпрямляется, нога
возвращается. Это работает для руки и **не работает** для ноги. В кадре
получается выпад: прямая нога выносится вперёд низом, и слабый удар ногой не
отличить от шага. Так и было, пока замер не сформулировали правильно.

Настоящий удар ногой — это три фазы, и колено с голенью живут в разных:

1. **Занос** (кадры `startup`): колено идёт вверх, голень ПОДЖИМАЕТСЯ, пятка
   к ягодице. Стопа остаётся у тела.
2. **Выхлест**: бедро стоит, голень выстреливает.
3. **Возврат** (кадры `recovery`): сначала складывается голень — быстро, за
   первые 40 % фазы, — и только потом опускается бедро.

Ключевая тонкость в том, **где заканчивается выхлест**. Естественно
растянуть его на активные кадры — и это ошибка: активные кадры и есть кадры
попадания, а значит к ПЕРВОМУ из них нога обязана быть уже выпрямлена.
Пока выхлест шёл по активным кадрам, стопа доезжала до цели уже на возврате:
хитбокс попадал, нога — нет. Поэтому обе фазы укладываются внутрь замаха:

```typescript
const chamberEnd = s * 0.55;                       // s = startup
if (elapsed <= chamberEnd) {                       // занос
  lift = smoothstep(elapsed / chamberEnd); snap = 0;
} else if (elapsed <= s + a) {                     // выхлест и удержание
  lift = 1; snap = smoothstep((elapsed - chamberEnd) / (s - chamberEnd));
} else {                                           // возврат
  const p = clamp((elapsed - s - a) / r, 0, 1);
  lift = 1 - smoothstep(p);
  snap = Math.max(0, 1 - p * 2.5);                 // голень складывается первой
}
```

Поджим голени растёт вместе с заносом (`fold = 0.25 + 1.05 * lift`), и удар
получается как удар, а не как вынос прямой ноги.

**Короткому приёму нужен утрированный занос.** У фронт-кика шесть кадров
замаха, а поза едет к цели экспоненциально с постоянной около четырёх
кадров — за шесть кадров она проходит чуть больше половины пути. С
«честной» глубиной заноса разница между поджатой и распрямлённой голенью
получалась 0.36 рад и на экране не читалась; с множителем 1.55 — 0.55 рад и
читается. Это та же поправка, что и у уклона (§6): цель обязана быть с
запасом, если фаза короче времени доезда.

Всё это — про позу-цель, то есть про запасной путь и про то, что уезжает в
библиотеку `assets/proc_anim/`. Когда мокап есть, бьющую ногу ведёт он (см.
подраздел выше), и фазы приходят из клипа сами.

Замер этой фазы формулируется прямо: найти кадр максимального выноса стопы
и сравнить сгиб бьющей голени **до** него с сгибом **в нём**. Пока обе фазы
вела одна дуга, эти два числа совпадали.

### Граница мокапа проходит по бьющей конечности

Позу удара ногой выше стоит держать как запасной путь — а в кадре ногу
лучше ведёт мокап, если он есть. Вопрос в том, **что именно из него брать**,
и слои «верх / всё» тут оба неправильные:

* «верх» отдаёт ноги позе-цели, и мокапная нога не участвует вообще — ради
  чего тогда записывали;
* «всё» отдаёт мокапу таз и ОПОРНУЮ ногу, а их ведёт игра: боец привязан к
  своей точке настила, и актёрский перенос веса отрывает ему стопу от пола.

Правильная граница — по бьющей конечности. Мокап ведёт ту ногу, которая
бьёт, плюс корпус; игра оставляет себе вторую ногу, таз и корень:

```typescript
roundhouse: {
  clip: 'combo_punch_kick', from: 0.35, to: 0.85,
  joints: ['waist', 'chest', 'thighR', 'shinR'],   // задняя нога — сторона R
},
```

Явный список суставов **никогда** не отдаёт корень, даже если в нём есть
таз: он для того и нужен, чтобы взять из клипа конечность, оставив игре её
точку на настиле.

И ещё одно, из той же серии «называйте вещи по тому, что видно». Клип для
слабого удара ногой нашёлся один — прямой удар стопой в корпус. Приём после
этого стал фронт-киком, а не лоу-киком: подгонять анимацию под название
значит завести третий источник правды после фрейм-даты и позы. Заодно у
трёх ударов ногами получились три разные высоты — корпус, голова, настил —
и три разных ответа.

### Удар ногой: поза обязана дотягиваться до собственного хитбокса

У удара рукой поза и попадание живут почти независимо: рука короткая, хитбокс
у головы, промахнуться позой на десять сантиметров незаметно. У ноги — нет.
Нога — самая длинная и самая заметная часть силуэта, и если хитбокс висит на
высоте головы, а стопа поднимается до колена, кадр читается как ошибка ещё до
того, как игрок поймёт, что именно не так.

Поэтому у ударов ногами замер не «нога сдвинулась», а **стопа оказалась
внутри коробки своего же приёма**:

```typescript
const box = MOVES[id].hitbox;
check('стопа доходит до своего хитбокса', foot.maxZ > box.x - box.w / 2);
check('стопа на высоте своего хитбокса', foot.maxLift > box.y - box.h / 2);
```

Именно этот замер и двигал коробки — причём в обе стороны, и это стоит
запомнить. Хайкик задумывался в голову (y = 1.5), а поза доносила стопу до
1.33 — коробка опустилась на 1.42. Слабый удар ногой на позе-цели доносил
стопу всего до 0.31 (удар по бедру), и коробка ушла вниз; когда ту же ногу
отдали мокапу, стопа поднялась до 0.94 — прямой удар в корпус, — и коробка
вернулась на 0.95. Каждый раз правым оказывалось не «дотянуть позу под
цифру», а признать, куда нога реально бьёт: подтягивание даёт кик из бедра
с выпрямленной в воздухе опорной ногой.

Три числа, которые делают кик киком:

* **Опорная нога сгибается.** Без этого боец машет ногой, стоя на прямой
  второй, и вес не читается вообще.
* **Корпус отклоняется назад пропорционально высоте ноги.** Иначе центр
  тяжести уезжает вперёд из-под бойца.
* **Таз не опускается на высоком ударе.** Каждый сантиметр приседа снимается
  с высоты стопы один к одному: у хайкика те же 10 см приседа, что у
  подсечки, съедали весь смысл приёма.

И общий знаменатель с §6: голень **никогда не переходит через ноль**.
Выпрямление в пике задаётся долей от сложенного состояния, а не отдельным
целевым углом:

```typescript
const fold = (0.25 + 1.05 * lift) * chamber;   // поджим растёт с заносом
const shin = -fold + snap * fold * extend;     // extend ≤ 1 → ноль не пройти
```

Любая формула, где голень может выйти в плюс, рано или поздно туда выйдет.

## 7. Как убедиться, что анимация не сломана

Поза ломается молча. Ни исключения, ни красного кадра: боец просто идёт с
прямыми ногами, стоит в стойке вместо приседа или уезжает коленями назад. В
матче это не поймать — удар живёт четыре кадра, подъём случается раз в
полминуты, а нужную фазу не остановить.

Работают две вещи вместе, и обе обязательны.

**Витрина анимаций.** Отдельная страница (`anim.html` в стенде), которая
рисует по шесть кадров на анимацию одним листом; Playwright снимает листы,
человек их смотрит. Ключевое требование: анимация должна вызываться
**нажатием тех же клавиш, что нажмёт игрок**, а не установкой состояния
снаружи. Мы начали с установки состояния, и витрина честно показывала
стойку под подписью «шаг»: игровая логика каждый кадр переустанавливает
состояние ходьбы по вводу и тут же затирала подставленное.

Нокдаун снимается той же витриной отдельной полосой — он не анимация (в
библиотеку клипов физику не выгрузишь), но ломается так же молча и в кадре
виден мгновенно. Кадры берутся чаще в начале (`[0, 8, 18, 32, 55, 90]`): за
первые полсекунды тело успевает всё, дальше оно просто лежит.

**Головные замеры той же игры.** Прогон без рендерера, те же клавиши, и
меряются числа, а не картинка: у джеба — насколько перчатка ушла вперёд от
гарда, у приседа — насколько опустилась голова, у шага — размах стопы и
сгиб колена, у уклона — сдвиг головы вбок, у прыжка — высота и наклон
корпуса, у любой анимации — не ушла ли стопа под пол. Мерить надо в системе
координат персонажа (`root.worldToLocal`), иначе развороты бойца всё портят.

Что этот набор поймал у нас за один заход:

* уклон жил **один кадр из тринадцати** — обработчик движения затирал
  состояние, потому что уклон не считался «занятым»; на экране его просто не
  было, а в бою он не уводил ни одного удара;
* шаг шёл прямыми ногами (одна общая переменная сгиба на обе голени);
* колено сгибалось не в той фазе — сгиб был привязан к выносу бедра, нога
  поджималась в крайней передней точке, и стопа вообще не уезжала вперёд:
  обе стопы всё время висели позади таза. Колено гнётся, когда нога
  **проходит под корпусом** (`cos(фаза)`), и распрямляется к постановке;
* темп ног не совпадал со скоростью тела: фаза шага крутилась временем, цикл
  занимал 1.4 с, а боец за это время проезжал семь метров. Выглядит это как
  «еле-еле переставляет ноги», хотя амплитуда нормальная. Крутите фазу
  **пройденным расстоянием**, а не временем — тогда стопа уходит назад ровно
  со скоростью настила и не скользит:
  `stepPhase += Math.PI * travel / STEP_LENGTH`;
* у приседа не было своей позы вообще — он опирался на клип, который
  опускает голову на 14 см;
* остаток поворота от мокапа не сбрасывался: поза-цель писала только те оси,
  которые меняла, и таз навсегда оставался повёрнутым на 0.23 рад;
* колени были выгнуты назад в девяти анимациях из двадцати — перепутанный
  знак поворота ноги (см. §6);
* в рэгдолле руки и ноги не были сшиты с телом — три сустава на восемь тел
  (см. §5).

Последние два нашлись только после того, как в набор добавились два новых
замера: **вынос колена вперёд** во всех анимациях и **число суставов
рэгдолла** плюс «уехала ли стопа вместе с тазом» за время падения. Общее
правило тут такое: замер должен проверять не «поза изменилась», а
**физический факт**, который в сломанном варианте нарушается. «Голова
опустилась на 30 см» проходит и с вывернутыми коленями; «колено впереди
линии бедро→лодыжка» — нет.

Последнее — общее правило: **каждый сустав каждый кадр возвращайте по всем
трём осям**, даже если анимация меняет одну. Иначе любой источник, писавший
в остальные (мокап, рэгдолл, предыдущее состояние), оставляет след навсегда.

## 8. Чек-лист

* [ ] Позвоночник из двух сегментов; таз и корпус — независимые корни.
* [ ] Каждая степень свободы — своя группа (плечо → локоть → предплечье).
* [ ] Разворот к цели через `root`, ±90° для боковой камеры, и он зеркалится.
* [ ] Есть шея, нос глубиной ≥ 0.07, суставы на сгибах, обувь выше щиколотки.
* [ ] Лицо и телосложение — от seed, не от `Math.random()`.
* [ ] Износ по зонам, накладки с `depthWrite: false` и `visible = false` при нуле.
* [ ] Рэгдолл использует меши персонажа; кости считаются «листья → корень»;
      `attach`, а не `add`; снимок локальных трансформов для возврата.
* [ ] Тела рэгдолла создаются одним проходом, а сшиваются **вторым**: список
      идёт «листья → корень», и родитель на момент своей кости ещё не создан.
* [ ] Колено проверено замером выноса вперёд — во **всех** анимациях, не
      только в шаге.
* [ ] Анимация — цели + один коэффициент приближения; дуга удара выводится
      из фрейм-даты; в `idle` персонаж никогда не стоит неподвижно.
* [ ] Каждый сустав возвращается к цели по всем трём осям, а не только по «своей».
* [ ] Каждая анимация вызывается клавишей и снята витриной (§7).
* [ ] Ни одна поза не уводит стопу под пол и не роняет голову ниже пояса.
* [ ] У ударов ногами стопа доходит до хитбокса своего же приёма — замером,
      а не на глаз; опорная нога согнута, корпус отклонён назад.
* [ ] Удар ногой разбит на занос, выхлест и возврат; выхлест заканчивается
      к первому активному кадру, а не к последнему.
* [ ] Рэгдолл — не меньше двенадцати тел: конечности разбиты по суставам.
* [ ] Колено и локоть — шарниры с пределами от текущей позы, а не шары.
* [ ] Нокдаун меряется тремя числами: разброс тела, высота головы в конце,
      нижняя точка коллайдеров.
