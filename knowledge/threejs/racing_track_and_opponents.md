# Гонка на Three.js: трасса, круги, гоночная линия и соперники

> 💡 **Интерактивное демо**: `workspace/knowledge-showcase/` (вкладка *«🏁 Гонка:
> трасса и соперники»*).
> Головная проверка: `npm run check:racing` — прогоняет бота 3 круга без рендерера
> и валидирует геометрию трассы, стабильность кругов и границы резинки.
> Именно она поймала реальный баг: сопротивление считалось «за кадр» вместо «за
> секунду», и машина упиралась в 44 км/ч вместо 187.

Управление машиной и занос — в `arcade_racing_and_drift.md` и
`rapier_vehicle_controller.md`. Здесь — то, что превращает «машину, которая ездит» в
**гонку**: замкнутая трасса, чекпойнты и круги, соперники и результат заезда.

## 1. Трасса — одна кривая, а не набор кусков

Вся геометрия трассы порождается **одним** `CatmullRomCurve3`. Это единственный
источник истины: из него получаются полотно, отбойники, чекпойнты, гоночная линия,
позиции старта, респавн и миникарта. Трасса, собранная из отдельных повёрнутых
сегментов, даёт уступ на каждом стыке (`CRITICAL_RULES` §64), а восстановление после
вылета становится нерешаемой задачей.

```typescript
const track = new THREE.CatmullRomCurve3(controlPoints, true, 'centripetal', 0.5);
const SAMPLES = 900;              // ~1 точка на 0.5 м для трассы 450 м
const pts = track.getSpacedPoints(SAMPLES);
```

Полотно строится протяжкой профиля вдоль кривой с **устойчивым** нормальным репером:
собственный «up» по кривой (Frenet) переворачивается на прямых участках и скручивает
дорогу.

```typescript
const frames = track.computeFrenetFrames(SAMPLES, true);
const up = new THREE.Vector3(0, 1, 0);

for (let i = 0; i <= SAMPLES; i++) {
  const p = pts[i % SAMPLES];
  const tan = frames.tangents[i];
  const right = new THREE.Vector3().crossVectors(tan, up).normalize();  // up-стабилизированный
  const bank = bankingAt(i);                                            // вираж, см. ниже
  right.applyAxisAngle(tan, bank);
  // левый и правый край полотна:
  left[i]  = p.clone().addScaledVector(right, -halfWidth);
  rightE[i] = p.clone().addScaledVector(right,  halfWidth);
}
```

* **Вираж (banking)** считается из кривизны: `bank = clamp(curvature * k, 0, 0.25 рад)`.
  Он не украшение — на аркадной физике вираж и есть причина держать газ в повороте.
* Коллайдер полотна — `RAPIER.ColliderDesc.trimesh()` **из тех же буферов**, что и
  видимый меш, и обязательно на `fixed`-теле.
* Отбойники — отдельная лента по краям с высоким трением и низким `restitution`
  (0.05): упругие отбойники отправляют игрока в космос.
* Ширина не постоянная: 12–16 м на прямых, 16–20 м в шпильках. Постоянная ширина —
  главный признак «сгенерированной» трассы.

## 2. Чекпойнты, круги и позиция в гонке

Чекпойнты — не «кольца на трассе», а **равномерная разметка кривой**. Из неё бесплатно
получаются круги, позиция в гонке, респавн и защита от срезок.

```typescript
const CHECKPOINTS = 40;                       // ~каждые 10 м
const cpPos = Array.from({ length: CHECKPOINTS }, (_, i) => track.getPointAt(i / CHECKPOINTS));

interface RaceProgress { lap: number; cp: number; distToNextCp: number; }

function updateProgress(car: Car): void {
  const next = (car.cp + 1) % CHECKPOINTS;
  if (car.pos.distanceTo(cpPos[next]) < CP_RADIUS) {
    car.cp = next;
    if (next === 0) car.lap++;                // круг засчитан только через нулевой чекпойнт
  }
}

// Позиция в заезде: сортировка по (круг, чекпойнт, -расстояние до следующего)
const score = (c: Car) => c.lap * CHECKPOINTS + c.cp + (1 - c.distToNextCp / CP_SPACING);
```

Правила:
1. Чекпойнты проходятся **строго по порядку**. Проверка «расстояние до любого» позволяет
   срезать половину трассы задом наперёд.
2. Круг засчитывается только при переходе `последний → 0`. Отдельная «линия финиша»
   как коллайдер даёт двойные засчёты при качании машины на линии.
3. **Респавн** — на `track.getPointAt(cp / CHECKPOINTS)` с касательной как направлением.
   Ручные точки респавна всегда рассинхронизируются с трассой после её правки.
4. «Не в ту сторону» определяется знаком `velocity · tangent`, а не таймером.

Круговое время меряется по `performance.now()` в момент засчёта круга, а не суммой
`dt`: накопленная ошибка `dt` за 3 минуты даёт расхождение с секундомером в десятые.

## 3. Гоночная линия и соперники

Соперники **не** едут по осевой линии — так они выглядят как поезд. Гоночная линия
смещена внутрь поворота: раннее внешнее положение, апекс у внутреннего края, широкий
выход.

```typescript
// offset в диапазоне [-1..1] от осевой: -1 = левый край, +1 = правый
function racingOffsetAt(t: number): number {
  const k = signedCurvature(t);                 // + = правый поворот
  const ahead = signedCurvature((t + 0.03) % 1);
  return THREE.MathUtils.clamp(-(k * 2.2 + ahead * 1.4), -0.85, 0.85);
}
```

Сгладить получившуюся линию один раз на старте (скользящее среднее по 9 точкам) и
запечь в массив — считать это каждый кадр не нужно.

**Соперник управляется тем же контроллером, что и игрок.** Бот, которому пишут
`position` напрямую, невозможно догнать, столкнуть или обогнать — гонка исчезает.
ИИ выдаёт только ввод:

```typescript
function driveAI(bot: Car, dt: number): VehicleInput {
  const lookahead = 6 + bot.speed * 0.35;                 // на скорости смотрим дальше
  const t = (bot.trackT + lookahead / trackLength) % 1;
  const target = pointOnRacingLine(t).addScaledVector(rightAt(t), bot.laneBias);

  const local = bot.worldToLocal(target.clone());
  const steer = THREE.MathUtils.clamp(local.x * 1.6, -1, 1);

  // Скорость входа в поворот из радиуса кривой, а не «газ до упора всегда»
  const rad = curvatureRadiusAhead(t);
  const vMax = Math.sqrt(LATERAL_GRIP * rad);
  const throttle = bot.speed < vMax ? 1 : 0;
  const brake = bot.speed > vMax * 1.12 ? 1 : 0;

  return { throttle, brake, steer, handbrake: false, recover: false };
}
```

* `lookahead`, растущий со скоростью, — главный параметр «качества вождения» бота.
  Фиксированный даёт виляние на прямых и вылеты в поворотах.
* `laneBias` (±0.4 ширины) у каждого бота свой и меняется при обгоне — иначе боты
  выстраиваются в одну колею и толкают друг друга.
* Обгон: если впереди машина ближе 8 м и её скорость ниже, бот смещает `laneBias` в
  сторону, где больше свободного места. Полноценный `ObstacleAvoidanceBehavior` из Yuka
  работает и здесь, но на трассе достаточно смещения полосы.
* Yuka `StateMachine` уместна для верхнего уровня: `Race → Overtake → Recover → Pit`.

## 4. Резинка (rubber-banding) — честная

Без подстройки гонка распадается на десять секунд: либо игрок уезжает, либо не догоняет.
Правильная резинка меняет **параметры вождения**, а не телепортирует:

```typescript
const gap = playerScore - bot.score;                    // в чекпойнтах
const k = THREE.MathUtils.clamp(gap * 0.02, -0.08, 0.12);
bot.maxSpeed = bot.baseMaxSpeed * (1 + k);              // ±8..12 %, не больше
bot.aggression = THREE.MathUtils.clamp(0.5 + gap * 0.05, 0.2, 1);
```

Границы `−8 % … +12 %` — не произвольные: за ними игрок замечает, что его «догоняют
магией», и гонка обесценивается. Отстающий бот **не** должен ехать быстрее личного
рекорда игрока на этом круге. Лидирующий бот замедляется только до `−8 %`, иначе
победа перестаёт что-то значить.

Ускорители, доступные только отстающим (слипстрим, «воздушный мешок»), работают лучше
резинки, потому что видимы игроку: он понимает, почему соперник догнал.

## 5. Слипстрим, нитро и поверхности

```typescript
// Слипстрим: за машиной впереди, в конусе 12°, до 25 м
const behind = leader.pos.clone().sub(car.pos);
const dist = behind.length();
if (dist < 25 && behind.normalize().dot(car.forward) > 0.97) {
  const strength = (1 - dist / 25) * 0.18;              // до +18 % тяги
  car.engineForce *= 1 + strength;
}
```

Нитро копится за поведение, а не за время: занос, слипстрим, «чистый» сектор без
касаний. Это единственный способ связать вождение с ресурсом.

Разные поверхности — разные `frictionSlip` колёс, и переключение **плавное** (lerp
0.2 с), иначе машина «щёлкает» на границе асфальт/гравий:

| Поверхность | frictionSlip | Эффект |
|---|---|---|
| Асфальт | 2.2 | база |
| Гравий/грунт | 1.4 | занос, пыль, −15 % скорости |
| Трава | 0.9 | сильный снос, замедление |
| Лужа/лёд | 0.6 | почти нет поперечного сцепления |

Определение поверхности — по материалу треугольника, в который попал луч колеса
(`three-mesh-bvh` по коллизионному мешу отдаёт `faceIndex` → группа материала).

## 6. Старт, финиш и мини-карта

* **Стартовая решётка**: позиции берутся с кривой (`getPointAt`) со смещением по
  `right`, шахматно, шаг 8 м. Машины ставятся `setTranslation` + `wakeUp`, а не
  создаются заново (`CRITICAL_RULES` §65).
* **Обратный отсчёт 3-2-1**: физика уже шагает (машины оседают на подвеске), ввод
  заблокирован. «Фальстарт» — штраф в 1.5 с, а не блокировка кнопок.
* **Мини-карта** — проекция той же кривой в 2D. Это ~40 строк: `getSpacedPoints`,
  нормировка по bounding box, отрисовка в отдельном ортографическом слое или в SVG.
  Никакой второй геометрии трассы для карты не заводится.
* **Финиш**: гонка заканчивается для игрока, но боты **дочитывают круг** — иначе
  таблица результатов заполняется мгновенно и не читается.

## 7. Чек-лист

* [ ] Вся трасса выведена из одной `CatmullRomCurve3`; коллайдер — из тех же буферов.
* [ ] Виражи считаются из кривизны, ширина переменная.
* [ ] Чекпойнты проходятся по порядку; круг — только через нулевой чекпойнт.
* [ ] Респавн и стартовая решётка берутся с кривой, а не из ручных точек.
* [ ] Боты ездят через тот же `VehicleInput`, что и игрок.
* [ ] Скорость входа в поворот считается из радиуса кривизны.
* [ ] Резинка ограничена ±8/12 % и не превышает лучший круг игрока.
* [ ] Смена поверхности плавная (lerp), не пороговая.
* [ ] Время круга — по `performance.now()`, не по сумме `dt`.
* [ ] Головной тест: бот проезжает 3 круга без вылетов и укладывается в целевое время.
