# Skill: Оптимизация высоконагруженного 2D-роя в PixiJS

## Purpose
Руководство по эффективному рендерингу тысяч частиц и расчету физических полей без падения FPS на веб-платформах.

## When to Use
При реализации симуляции движения роя, феромонных сеток и систем сцепки юнитов.

## Core Rules & Constraints
- Использовать ParticleContainer для всех стандартных муравьев
- Хранить координаты и скорости в типизированных массивах Float32Array
- Избегать создания новых объектов (GC allocations) внутри функции animate/tick
- Обновлять текстуру феромонов через кастомный WebGL шейдер или низкоуровневый буфер

## System Architecture
SwarmEngine оперирует единым пулом частиц (Object Pooling) и производит вычисления сил в одном проходе цикла с использованием сетки пространственного разделения (Spatial Hash).

## Implementation Guidance
Разбивайте поле боя на ячейки 64x64 пикселей. Проверяйте коллизии и сцепку только между муравьями внутри соседних ячеек сетки.

## Common Mistakes to Avoid
- ❌ **Mistake**: Создание отдельного PixiJS Graphics объекта для каждого муравья
- ❌ **Mistake**: Использование стандартных массивов Array.push / filter в главном цикле рендера
- ❌ **Mistake**: Частые вызовы getBoundingClientRect или тяжелых проверок столкновений

## Validation Checklist
- [ ] Все муравьи инстансированы в ParticleContainer
- [ ] В цикле обновления нет вызовов new Object() / new Array()
- [ ] Сетка пространственного хеширования очищается и заполняется за один проход
- [ ] FPS на мобильном устройстве держится выше 55 кадров
