# UI/UX Specification: Громовой Перехват: Штормовой Экспресс

## 1. Материал интерфейса
Интерфейс живёт в том же мире, что и сцена. Проверка: если закрыть игровое поле,
меню обязано выдавать именно эту игру, а не любую другую.

- **Тема от арт-директора**: Диегетический голографический визор шлема: светящиеся бирюзовые векторные шкалы, медные аналоговые индикаторы и изогнутая аэродинамическая сетка упреждения
- **Визуальный язык**: Бирюзовый (#00F0FF) — маркеры прицеливания, дружественные энергополя, союзные тесла-дуги; Оранжево-красный (#FF6B00 / #FF003C) — траектории летящих обломков, плазма вражеских дронов, критические предупреждения; Медно-желтый (#B87333) — механические элементы поезда, ранги и шестеренки прогрессии.
- **Типографика**: Заголовки: 'Orbitron', bold, sans-serif (футуристичный теслапанк); Числовые шкалы и таймеры: 'Share Tech Mono', monospace; Интерфейсный текст: 'Roboto', medium, sans-serif.

## 2. Акценты: один цвет — один смысл
Разный цвет у каждой кнопки «чтобы отличались» — главная ошибка игрового
интерфейса. На одном экране одновременно видно не больше двух акцентов.

| Токен | Единственный смысл |
|---|---|
| `Critical Threat / Debris Hazard` | #FF003C |
| `Hardware / Framing` | #B87333 |
| `Interactive / Lead Target` | #00F0FF |
| `Progress / Charge` | #7B2CBF |
| `Warning / Projectile Path` | #FF6B00 |

Все значения — токенами в `src/ui/theme.css`: цвета, гарнитуры, шкала отступов,
радиусы, длительности, порядок слоёв `--z-*`. Литерал цвета внутри экрана — баг.

## 3. Композиция экрана
Меню и экраны между сессиями лежат ПОВЕРХ живой игровой сцены — той же, что в
игре, только с медленной камерой. Непрозрачная заливка на весь экран запрещена:
подложка только под текстом и кнопками.

- **Сцена за меню**: Камера закреплена на носу мчащегося локомотива: впереди сквозь шторм убегают вдаль освещенные молниями рельсы, на переднем плане вибрирует тесла-карабин на оружейном станке

Экран — не колонка кнопок по центру. Три зоны, и каждый элемент лежит ровно в одной:

1. **Идентичность** — что это за экран: заголовок, режим, состояние игрока.
2. **Главное действие** — ровно одно на экран, самое крупное и единственное с
   основным акцентом.
3. **Второстепенный ряд** — всё остальное, одним рядом или сеткой, одним весом.

Зоны нажатия: основная ≥ 96 px, остальные ≥ 64 px, зазор ≥ 12 px, отступы через
`env(safe-area-inset-*)` плюс измеренная высота липкого баннера. Ни один экран не
скроллит страницу: длинный список скроллится во внутреннем контейнере.

## 4. Набор компонентов (закрытый)
Всё на экране — один из этих компонентов. Одноразовый `<div>` с инлайновыми
стилями — это то, из-за чего второй экран перестаёт совпадать с первым.

- DynamicReticle: Компонент прицела с адаптивной дугой упреждения и шейдерным свечением
- DebrisWarningBadge: Всплывающий маркер опасности с таймером столкновения
- CapacitorRingHUD: Круговой сегментированный индикатор заряда с шейдером тока
- TrainProgressTracker: Горизонтальный трекер состава со схемой вагонов и босса
- ResultRankCard: Карточка ранга (S/A/B) с анимацией печати и пересчетом очков

Каждый интерактивный компонент несёт пять состояний: покой, наведение, нажатие,
недоступность, `:focus-visible`; асинхронное действие — ещё и `loading`.

## 5. HUD
Не больше пяти постоянных элементов на телефоне. Пять якорей, посередине экрана
не висит ничего, кроме временной обратной связи.

| Якорь | Что там |
|---|---|
| `bottom_left` | MobileStrafeHelperZones |
| `bottom_right` | OverchargeButton & ComboMultiplier |
| `center` | DynamicLeadReticle & DebrisWarningBadges |
| `top_center` | TrainProgressTracker & StormZoneIndicator |
| `top_left` | ShieldBar & HealthStatus |
| `top_right` | Speedometer & WindGauge |

Элементы:
- Изогнутая ветровая шкала упреждения в центре экрана с динамическим маркером смещения
- Индикатор встречной скорости поезда (200-250 км/ч) и анемометр ветра (м/с)
- Сегментированная дуга прочности энергощита визора (3 деления)
- Круговой индикатор заряда комбо-конденсатора Тесла (0-100%)
- Мини-карта состава: прогресс продвижения по 5 вагонам к локомотиву
- Предупреждающие стрелки набегающих обломков (DANGER TRAJECTORY)

Меняющиеся числа — `tabular-nums` в слоте фиксированной ширины, полосы —
`transform: scaleX()`, а не `width`. Текст поверх геймплея всегда с подложкой или
обводкой: белое число исчезает на светлой сцене.

## 6. Состояние, показанное миром, а не оверлеем
- Анемометр с вращающимися медными чашечками на стволе карабина
- Стеклянный вольтметр на ствольной коробке, отображающий заряд конденсатора
- Капли дождя и трещины на визоре шлема при получении урона

## 7. Каталог экранов
### Экран: MAIN MENU
- **Что на экране**: Старт забега, выбор визора, доступ к лидерборду и настройкам
- **Композиция**: Три зоны: чем экран себя называет, единственное главное действие, второстепенный ряд одним весом. Меню лежит поверх живой сцены.

### Экран: HUD INGAME
- **Что на экране**: Отображение боевой информации, прицела и угроз во время рейда
- **Композиция**: Три зоны: чем экран себя называет, единственное главное действие, второстепенный ряд одним весом. Меню лежит поверх живой сцены.

### Экран: PAUSE MODAL
- **Что на экране**: Пауза геймплея, регулировка звука и чувствительности мыши/тача
- **Композиция**: Три зоны: чем экран себя называет, единственное главное действие, второстепенный ряд одним весом. Меню лежит поверх живой сцены.

### Экран: VICTORY SCREEN
- **Что на экране**: Показ финального времени, очков зачистки, ранга (S/A/B) и множителя наград
- **Композиция**: Три зоны: чем экран себя называет, единственное главное действие, второстепенный ряд одним весом. Меню лежит поверх живой сцены.

### Экран: DEFEAT MODAL
- **Что на экране**: Экран критического повреждения щита с кнопкой Revive (Rewarded Ad) и кнопкой рестарта
- **Композиция**: Три зоны: чем экран себя называет, единственное главное действие, второстепенный ряд одним весом. Меню лежит поверх живой сцены.

**Переходы**: MAIN_MENU -> RAID_INTRO_ANIMATION (поезд набирает 200 км/ч) -> HUD_INGAME (рейд 80 с) -> [VICTORY_SCREEN / DEFEAT_MODAL] -> REWARD_DOUBLER -> MAIN_MENU

## 8. Состояния экрана
- Loading State: Скелетная загрузка 3D моделей с анимированным логотипом поезда
- In-Game Active: Минималистичный HUD с максимальной читаемостью боевой зоны
- Ad State: Полное замораживание логики, заглушение звука и плавный возврат в строй
- Network Disconnect: Локальный фоллбэк сохранений через LocalStorage

## 9. Отклик и движение
- Точное попадание в упреждающий маркер: Неоново-белая вспышка прицела + сухой звук разряда + мгновенный рост комбо
- Цепная детонация звена: Ослепительная тесла-дуга + треск взрывов + вибрация устройства
- Близкий пролет обломка: Огненный шлейф на весь экран + свист ветра + крен камеры
- Прыжок через сцепку: Сноп искр под ногами + звон колес + короткое падение камеры с пружинящим приземлением

Переход один на всю игру и укладывается в 300 мс; анимируются только `transform`
и `opacity`; `prefers-reduced-motion: reduce` убирает трансформации.

## 11. Чек-лист приёмки интерфейса
- [ ] Ни одного литерала цвета, шрифта, радиуса или длительности вне `theme.css`.
- [ ] Слои над канвасом не перехватывают игровой ввод: контейнеры `pointer-events: none`.
- [ ] Каждый экран помещается в измеренный вьюпорт, страница не скроллится.
- [ ] Одно главное действие на экран, не больше двух акцентов одновременно.
- [ ] Меняющиеся числа не дёргают строку HUD.
- [ ] У каждого экрана описаны загрузка, пустота и ошибка.
- [ ] Возможность, которой нет на площадке, не нарисована вовсе.
- [ ] Ни `alert`/`confirm`, ни эмодзи вместо иконок, ни `z-index` мимо токенов.
- [ ] Самая длинная переведённая строка помещается в кнопку.
- [ ] За меню видна живая сцена игры, а не заливка цветом.
- [ ] Ни одного эмодзи в подписи кнопки: иконка — инлайновый SVG с `currentColor`.
- [ ] У каждого экрана расписаны три зоны, а не «карточка по центру».
- [ ] С закрытым игровым полем меню всё ещё узнаётся как «Громовой Перехват: Штормовой Экспресс».
