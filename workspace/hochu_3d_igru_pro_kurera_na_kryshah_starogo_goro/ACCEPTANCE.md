# Приёмка: Черепичный Спринт: Чистый Флоу

Готовность игры определяется этим файлом, а не ощущением. Каждый пункт — либо
команда с ожидаемым результатом, либо факт, который видно на экране. Пока хотя
бы один пункт раздела **A–C** красный, игра не готова: это не качество, это
работоспособность.

Автоматическая часть запускается одной командой:

```bash
node scripts/check-spec.mjs        # или npm run check:spec
```

Скрипт лежит в проекте и проверяет то, что проверяется статически. Остальное —
руками, по этому же списку. Результат прогона записывается в `DEVLOG.md`.

## C. Платформа Playgama

Без этого раздела игра не запускается на площадке — не «работает хуже», а не
стартует и снимается с модерации.

- [ ] **C1** · `game_ready` отправляется РОВНО ОДИН РАЗ и только после загрузки, когда меню уже интерактивно.
- [ ] **C2** · `bridge.initialize()` обёрнут таймаутом (~10 с), сторожевой таймер (~15 с) отправляет `game_ready` в любом случае.
- [ ] **C3** · Прогресс загрузки идёт от реальных вех, заставка доходит до 100% до `game_ready`.
- [ ] **C4** · Ни один шаг загрузки не ждёт решения игрока: `authorize()` в загрузке отсутствует.
- [ ] **C5** · Сохранение — один ключ (`courier_rank`), один JSON, нормализация при чтении; битый сейв поднимается на умолчаниях.
- [ ] **C6** · Награда за rewarded выдаётся только по `state === 'rewarded'` (Страховка Гильдии (Второе дыхание)), слушатель снимается через `off()`, повторный клик не платит дважды.
- [ ] **C7** · Interstitial не показывается при старте, в середине геймплея и сразу после покупки; пауза между показами соблюдена.
- [ ] **C8** · Пауза и звук приходят из событий моста (`PAUSE_STATE_CHANGED` / `AUDIO_STATE_CHANGED`), дельта времени сбрасывается при возврате.
- [ ] **C9** · Возможность, которой на площадке нет, не нарисована вовсе — не серой кнопкой и не ошибкой по нажатию. Проверяется подменой флага (best_delivery_time_royal_district).
- [ ] **C10** · Покупки: `getPurchases()` при каждом запуске, сначала выдача, потом `consumePurchase(productId)`.
- [ ] **C11** · Игра проверена в фрейме площадки и гостем, и авторизованным.

## H. Чек-листы отобранных документов базы знаний

Каждый пункт ниже — уже починенная кем-то ошибка, взятая из документа базы
дословно. Пункты проверяются взглядом на запущенную игру.

**Отметить обязан каждый.** `- [x]` — сделано. Пункт, который в этой игре не
нужен, помечается `- [~]` и строкой причины сразу после него: «не делаем,
потому что …». Оставленный пустым `- [ ]` считается невыполненным, и
`check-spec` не даст закрыть проект.

### `patterns/score_attack_loop.md`

- [ ] Множитель держится рискованными действиями и падает при простое
- [ ] Скорость растёт непрерывно, запас на ошибку сокращается
- [ ] Режим ярости даёт короткую неуязвимость и всплеск очков, и это читается по экрану
- [ ] Проигрыш мгновенный и понятный: игрок видит, обо что он ударился
- [ ] Результат уходит в таблицу лидеров сразу после смерти
- [ ] Рестарт мгновенный, без загрузки: «ещё один раз» не упирается в экран ожидания

### `threejs/performance_guide.md`

- [ ] Повторяющиеся объекты (враги, снаряды, обломки, трава) — через InstancedMesh, а не отдельными мешами
- [ ] Статичное окружение слито в общую геометрию
- [ ] В кадре меньше 50 000 активных треугольников
- [ ] Геометрии, материалы и текстуры освобождаются при смене сцены
- [ ] Один направленный свет с тенями; заполняющий — ambient или hemisphere, а не россыпь точечных
- [ ] Карта теней не больше 1024 на мобильном
- [ ] pixelRatio ограничен 1.5 на мобильном
- [ ] Дельта времени ограничена сверху: возврат из свёрнутой вкладки не взрывает физику

### `threejs/physics_integration.md`

- [ ] Движок выбран под задачу: Rapier для тысяч тел, рэгдоллов и рейкастов, Cannon-es для простых аркадных столкновений
- [ ] Порядок кадра: силы → шаг мира → синхронизация мешей, а не наоборот
- [ ] Позиция меша интерполируется между физическими шагами, иначе видно дрожание
- [ ] Суставы рэгдолла имеют пределы углов, линейное и угловое затухание — без этого он трясётся
- [ ] Тела и суставы освобождаются явно: память WASM не собирается сборщиком мусора
- [ ] Шаг физики фиксированный, а накопитель ограничен сверху

### `threejs/procedural_mesh_builder.md`

- [ ] Модели собираются процедурно в коде, без внешних GLTF
- [ ] Силуэт читается на расстоянии: персонаж отличается от врага формой, а не только цветом
- [ ] Геометрия переиспользуется между экземплярами, а не создаётся заново на каждый объект
- [ ] metalness ≤ 0.4 или задан scene.environment — иначе металл выглядит чёрным
- [ ] Анимация персонажа идёт поворотами костей или групп, а не подменой мешей
- [ ] Число материалов ограничено: каждый новый материал — отдельный draw call

### `threejs/game_map_and_world_design.md`

- [ ] **Вид сверху (Top-Down Overview)**: все участки трассы изолированы, встречные полосы не пересекаются, нет самопересечений сплайна.
- [ ] **Стартовая зона**: стартовые слоты ориентированы строго по направлению движения, светофоры и арка развернуты навстречу машинам, трибуны не залезают на полотно.
- [ ] **Разметка**: белые линии идут параллельно кромке, пунктир не имеет поперечных стяжек, отсутствует мерцание (Z-fighting).
- [ ] **Кромка дороги и поребрики**: переход в повороты гладкий, без зазубрин; поребрики лежат точно на внутренних апексах.
- [ ] **Заземление декораций**: деревья, столбы, таблички торможения и барьеры надежно стоят на поверхности холмов без левитации.
- [ ] **Физика**: болиды и соперники стартуют вперед, проходят первый поворот на скорости без переворотов и провалов сквозь полигоны.

### `threejs/procedural_character_rig.md`

- [ ] Позвоночник из двух сегментов; таз и корпус — независимые корни.
- [ ] Каждая степень свободы — своя группа (плечо → локоть → предплечье).
- [ ] Разворот к цели через `root`, ±90° для боковой камеры, и он зеркалится.
- [ ] Есть шея, нос глубиной ≥ 0.07, суставы на сгибах, обувь выше щиколотки.
- [ ] Лицо и телосложение — от seed, не от `Math.random()`.
- [ ] Износ по зонам, накладки с `depthWrite: false` и `visible = false` при нуле.
- [ ] Рэгдолл использует меши персонажа; кости считаются «листья → корень»;
- [ ] Тела рэгдолла создаются одним проходом, а сшиваются **вторым**: список
- [ ] Колено проверено замером выноса вперёд — во **всех** анимациях, не
- [ ] Анимация — цели + один коэффициент приближения; дуга удара выводится
- [ ] Каждый сустав возвращается к цели по всем трём осям, а не только по «своей».
- [ ] Каждая анимация вызывается клавишей и снята витриной (§7).
- [ ] Ни одна поза не уводит стопу под пол и не роняет голову ниже пояса.
- [ ] У ударов ногами стопа доходит до хитбокса своего же приёма — замером,
- [ ] Удар ногой разбит на занос, выхлест и возврат; выхлест заканчивается
- [ ] Рэгдолл — не меньше двенадцати тел: конечности разбиты по суставам.
- [ ] Колено и локоть — шарниры с пределами от текущей позы, а не шары.
- [ ] Нокдаун меряется тремя числами: разброс тела, высота головы в конце,

- [ ] Частицы живут в пуле на InstancedMesh, без аллокаций в кадре

## Как отчитываться

Прогон приёмки записывается в `DEVLOG.md` строкой вида:

```text
2026-01-01 приёмка: A1–A4 ✅, B1–B12 ✅, C1–C11 ✅, D1–D5 ✅, E1–E5 частично (E1 на телефоне 48 FPS), F1–F4 ✅, G1–G10 ✅, H1 ✅ (2 осознанных отказа)
```

Пункт, который не проходит, честнее оставить красным с объяснением, чем
отметить зелёным: следующий, кто откроет проект, будет считать его проверенным.
