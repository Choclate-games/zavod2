# Skill: Оптимизация Three.js

## Purpose
Удержать стабильную частоту кадров при первом лице, динамическом освещении и выборочных физических разрушениях.

## When to Use
До сборки мобильного вертикального среза и при любой просадке ниже целевого бюджета.

## Core Rules & Constraints
- Измерять кадр до изменения качества.
- Ограничивать динамические тела, тени и вызовы отрисовки.
- Не создавать временные объекты в цикле прицела.
- Проверять стабильность качества на мобильных устройствах.

## System Architecture
Разделить сцену на активный павильон, отключённые дальние павильоны, слой физики и слой HUD.

## Implementation Guidance
Использовать пул трассеров и частиц, заранее подготовленные состояния декораций и адаптивное качество только по измеренной частоте кадров.

## Common Mistakes to Avoid
- ❌ **Mistake**: Оставлять физику всех павильонов активной.
- ❌ **Mistake**: Пересоздавать геометрию после каждого разрушения.
- ❌ **Mistake**: Привязывать отдачу к количеству кадров.
- ❌ **Mistake**: Включать динамические тени на всех объектах.

## Validation Checklist
- [ ] Проверить 60 кадров в секунду на настольном браузере.
- [ ] Проверить 45 кадров в секунду на среднем телефоне.
- [ ] Проверить каскад из 18 динамических тел.
- [ ] Проверить отсутствие аллокаций в цикле прицела.
