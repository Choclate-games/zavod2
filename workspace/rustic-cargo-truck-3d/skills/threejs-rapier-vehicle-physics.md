# Skill: Three.js & Rapier3D Vehicle and Cargo Controller

## Purpose
Обеспечить стабильную симуляцию физики грузовика с raycast-подвеской и коллизиями груза в веб-среде.

## When to Use
При любой правке контроллера машины, взаимодействия колёс с грунтом или симуляции предметов в кузове.

## Core Rules & Constraints
- Кузов — один `RigidBody` + `DynamicRayCastVehicleController`. Колёса это лучи подвески, а не отдельные тела.
- **Никогда** не назначать скорость кузову каждый кадр (`setLinvel`) — это затирает солвер, убивает подвеску и делает колёса декорацией.
- `vehicle.updateVehicle(dt)` вызывается **до** `world.step()`.
- Лучи колёс фильтруются группами столкновений на грунт, иначе машина встаёт на собственный груз.
- Визуальные колёса — **дети группы кузова**. Ход подвески, угол руля и качение читаются у контроллера (`wheelSuspensionLength` / `wheelSteering` / `wheelRotation`), а не досчитываются вручную.
- Одна группа — одна степень свободы: `steer` рулит, вложенная `spin` катится.
- Борта кузова — часть составного коллайдера. Груз спавнится по слотам в локальных осях кузова и не пересекает коллайдеры машины.
- Рестарт заезда телепортирует существующие тела; меши и тела не пересобираются.
- Габариты, массы и тюнинг живут в `src/vehicle/truckSpec.ts` — модуле без зависимости от рендера, по которому гоняется хедлесс-проверка.

## System Architecture
`TruckController` владеет шасси, составным коллайдером (рама, кабина, четыре борта) и vehicle controller'ом.
Группа кузова синхронизируется с телом целиком — позиция **и** кватернион, — а риги колёс висят на ней.
`CargoManager` спавнит груз по слотам из `truckSpec` и гасит выпавшие тела через `setEnabled(false)`.
Рельеф — одна лента вершин из `src/world/terrain.ts`; коллайдер строится из тех же буферов, что и видимый меш.

## Implementation Guidance
Тюнинг подвески считается, а не подбирается: статическая просадка ≈ `gravity / stiffness`, а `restLength`
берётся заметно больше просадки. Тяга задаётся спадом силы к максималке (`force * (1 - speed / maxSpeed)`),
а не жёстким клэмпом скорости, иначе рельеф перестаёт влиять на игру.
Полный разбор с цифрами, ловушками API и чек-листом — `knowledge/threejs/rapier_vehicle_controller.md`
и `knowledge/threejs/vehicle_wheel_rig.md` (§0 и §3b — про физические машины).

## Common Mistakes to Avoid
- ❌ **Mistake**: `setLinvel` каждый кадр — машина едет вдоль мировой оси независимо от того, куда смотрит нос.
- ❌ **Mistake**: отдельный `wheelRoot`, копирующий только `translation()` — колёса отваливаются от кузова, детали наслаиваются.
- ❌ **Mistake**: `vehicle.setIndexForwardAxis(2)` — это **сеттер**, правильно `vehicle.setIndexForwardAxis = 2`.
- ❌ **Mistake**: груз, спавнящийся внутри коллайдера кузова — выстреливает наружу на первом кадре.
- ❌ **Mistake**: Trimesh для динамического кузова (в Rapier Trimesh только статический).
- ❌ **Mistake**: дорога из отдельных повёрнутых боксов — ступенька на каждом стыке.
- ❌ **Mistake**: отсутствие деактивации выпавших брёвен.

## Validation Checklist
- [ ] `npm run check:physics` проходит целиком (это дешевле и надёжнее визуальной проверки).
- [ ] В покое все четыре колеса в контакте, ход подвески одинаковый и внутри `maxTravel`.
- [ ] Полный газ: машина разгоняется, колёса крутятся вперёд, максималка близка к тюнингу.
- [ ] Руль вправо — машина едет вправо (проверка на зеркальность).
- [ ] Подвеска амортизирует кочки без бесконечной раскачки.
- [ ] Груз стабильно лежит в кузове при спокойной езде.
- [ ] Второй и третий заезды идентичны первому.
