# Приёмка: Огненный Каньон: Водный Сброс

Готовность игры определяется этим файлом, а не ощущением. Каждый пункт — либо
команда с ожидаемым результатом, либо факт, который видно на экране. Пока хотя
бы один пункт разделов **0–C** красный, игра не готова. Раздел **0** — то, что
пользователь заказал: игра, не прошедшая его, не принимается вообще, какой бы
удачной она ни вышла сама по себе. Разделы **A–C** — работоспособность, а не
качество.

Автоматическая часть запускается одной командой:

```bash
node scripts/check-spec.mjs        # или npm run check:spec
node scripts/smoke.mjs             # или npm run smoke — единственная проверка, которая открывает игру
```

Скрипт лежит в проекте и проверяет то, что проверяется статически. Остальное —
руками, по этому же списку. Результат прогона записывается в `DEVLOG.md`.

## H. Чек-листы отобранных документов базы знаний

Каждый пункт ниже — уже починенная кем-то ошибка, взятая из документа базы
дословно. Пункты проверяются взглядом на запущенную игру.

**Отметить обязан каждый.** `- [x]` — сделано. Пункт, который в этой игре не
нужен, помечается `- [~]` и строкой причины сразу после него: «не делаем,
потому что …». Оставленный пустым `- [ ]` считается невыполненным, и
`check-spec` не даст закрыть проект.

### `patterns/score_attack_loop.md`

- [ ] Множитель держится рискованными действиями и падает при простое
- [ ] Скорость растёт непрерывно, запас на ошибку сокращается
- [ ] Режим ярости даёт короткую неуязвимость и всплеск очков, и это читается по экрану
- [ ] Проигрыш мгновенный и понятный: игрок видит, обо что он ударился
- [ ] Результат уходит в таблицу лидеров сразу после смерти
- [ ] Рестарт мгновенный, без загрузки: «ещё один раз» не упирается в экран ожидания

### `mechanics/fluid_buoyancy.md`

- [ ] Выталкивающая сила считается по погружённому объёму, а не по факту касания воды
- [ ] Есть гидродинамическое сопротивление, иначе тело разгоняется в воде бесконечно
- [ ] Волны задаются суммой синусоид, и корпус наклоняется по нормали поверхности
- [ ] Качка не переходит в раскачку до переворота: демпфирование подобрано
- [ ] Тела разной плотности ведут себя по-разному: что-то тонет, что-то всплывает
- [ ] Вход в воду сопровождается всплеском и сменой звука

- [ ] Физика только на Rapier: свои «скорости», Cannon-es и ammo.js в проект не тянутся

- [ ] Рестарт уровня — телепорт тел, а не пересборка мира

## Как отчитываться

Прогон приёмки записывается в `DEVLOG.md` строкой вида:

```text
2026-01-01 приёмка: O1 ✅, A1–A5 ✅, S1–S7 ✅, B1–B12 ✅, C1–C12 ✅, D1–D5 ✅, E1–E5 частично (E1 на телефоне 48 FPS), F1–F4 ✅, G1–G13 ✅, H1 ✅ (2 осознанных отказа)
```

Пункт, который не проходит, честнее оставить красным с объяснением, чем
отметить зелёным: следующий, кто откроет проект, будет считать его проверенным.
