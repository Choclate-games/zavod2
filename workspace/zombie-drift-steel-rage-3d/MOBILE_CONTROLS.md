# MOBILE_CONTROLS.md — обязательный контракт тач-управления

Игра «Зомби Дрифт: Стальная Ярость 3D» обязана иметь полноценное мобильное
управление. Этот файл — единственный источник правды о раскладке, поведении
и требованиях к тач-вводу. Любое изменение в `src/ui/TouchControls.ts` или
`src/core/InputManager.ts` должно ему соответствовать.

## 1. Платформа и события

- Ввод только на **Pointer Events** (`pointerdown` / `pointermove` / `pointerup` /
  `pointercancel` / `lostpointercapture`). Это даёт мультитач и работу мышью
  для отладки на десктопе без эмулятора.
- Мультитач обязателен: руль + ГАЗ + НИТРО держатся одновременно разными
  пальцами. Различение пальцев — по `pointerId`, не по координатам.
- `setPointerCapture` на каждом элементе, чтобы жест не терялся, если палец
  ушёл за пределы кнопки/зоны.

## 2. Раскладка (ландшафт)

```
┌───────────────────────────────┬───────────────────────────────┐
│  ЛЕВАЯ ПОЛОВИНА (стик)        │  ПРАВАЯ ПОЛОВИНА (кнопки)      │
│                               │                                │
│  ПЛАВАЮЩИЙ ДЖОЙСТИК            │   [НИТРО]                      │
│  горизонталь = руль           │   [ДРИФТ]                      │
│  вертикаль   = газ / назад    │                                │
│  (появляется под пальцем      │   [ II ] <- пауза (сверху)     │
│   в любой точке зоны)         │                                │
└───────────────────────────────┴───────────────────────────────┘
```

- **Стик (левая зона, ~45% ширины):** плавающий джойстик. База возникает в точке
  касания, стик не привязан к фиксированному месту — удобно под любую руку.
  - Горизонталь — поворот (`steering` −1..+1).
  - Вертикаль — газ/назад (`throttle`): вверх = вперёд (+1), вниз = назад (−1).
  - Мёртвая зона ~8% по каждой оси гасит дрожание пальца. Обе оси работают
    одновременно, поэтому можно давить газ и доворачивать руль в одном жесте.
- **НИТРО:** `nitro` (удержание). **ДРИФТ:** `handbrake` (удержание) для
  управляемого заноса. Кнопки — справа снизу, мультитач с рулём.
- **ПАУЗА:** кнопка `II` в правом верхнем углу слоя управления (всегда поверх
  зон, `pointer-events: auto`, `z-index: 26`). Дублирует HUD-кнопку паузы, но
  не перекрывается зоной управления. Тап → `TOGGLE_PAUSE`.

Раскладка «один стик (руль+газ) + две кнопки (нитро, дрифт)»: для дрифт-аркады
нужно одновременно давить газ и доворачивать руль — это делается одним стиком,
а нитро и дрифт берутся свободными пальцами на отдельных кнопках.

## 3. Отмена браузерных жестов

- `touch-action: none` на `#game-container`, его `<canvas>` и слое `#touch-controls`.
- `contextmenu` — `preventDefault()` на `#game-container`.
- `touchmove` — `preventDefault({ passive: false })` на `#game-container` (нет
  скролла, pull-to-refresh, rubber-band).
- `dragstart` — `preventDefault()` на `#game-container`.
- Дублирующие гварды на слое `#touch-controls` (изоляция от меню/модалок).

## 4. Safe-area

- Все отступы кнопок/стик-зоны используют `env(safe-area-inset-*)`
  (left/right/bottom), чтобы управление не упиралось в чёлку/домашнюю полосу
  iPhone и системные жесты Android.
- На низких экранах в ландшафте (`max-height: 460px`) кнопки уменьшаются, чтобы
  не съедать обзор.

## 5. Видимость

- Управление показывается **только во время заезда** (`UIManager.showHud()`).
- В меню, гараже, паузе, экране выбора улучшения и Game Over слой скрыт
  (`display: none`), чтобы кнопки не перехватывали тапы по интерфейсу.
- При скрытии вызывается `releaseAll()`: все виртуальные кнопки и руль
  сбрасываются в 0, иначе машина уедет с зажатым газом.
- При `blur` окна и `visibilitychange` (сворачивание вкладки) — `releaseAll()`.

## 6. Включение / отладка

- Авто-включение: сенсорное устройство, `(pointer: coarse)` или ширина < 900px.
- Принудительное включение для проверки мышью на ПК: `?touch=1`.
- Принудительное отключение: `?touch=0`.

## 7. Производительность

- Путь ввода **не аллоцирует** в цикле 60 FPS: `InputManager.update()` отдаёт
  переиспользуемый объект `controls`, `TouchControls` пишет скаляры напрямую.
- Ввод событийно-ориентированный (только на `pointermove`), не опрашивается
  каждый кадр — задержка реакции минимальна, управление отзывчиво при 60 FPS.
